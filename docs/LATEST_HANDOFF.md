# 회사에서 이어가기 — 폐품로봇 원정대 / 2026-09-23

## 최신 구현: 엔진 회복과 챕터 1 다섯 구역

콘텐츠 `0.8.0-chapter-one`. 엔진은 처음/최대 5개, 일반·연습 원정 새 참가당 1개, 서버 시계로 30분마다 1개 회복한다. 오프라인 회복과 기존 기록을 지원하며, 살아 있는 같은 원정에 재접속하면 추가 차감하지 않는다. 거절된 입장도 차감하지 않는다. 홈/스테이지에 엔진 수, 출발 버튼에 비용, 별도 충전 창에 다음 회복 시간을 표시한다.

| 스테이지 | 배치 수 | 목표 | 최대 시간 |
|---|---:|---|---|
| 1-1 착륙 지대 | 30 | 적체 방어 + 보스 | 8:12 |
| 1-2 채굴장 | 28 | 채굴기 보호 | 26:40 |
| 1-3 엔진 기지 | 26 | 엔진 보호 + 보스 | 30:06 |
| 1-4 좁은 협곡 | 22 | 10분 방어 + 보스 | 11:30 |
| 1-5 탈출항 | 24 | 엔진을 15분 보호 + 보스 | 16:30 |

같은 행성 배경에 경로·배치 좌표·랜드마크를 다르게 넣었다. 서버/Canvas/자동 플레이 도구가 공용 geometry를 사용한다. 기존 1~3의 시간/목표/연구 기록, 확률/조합식은 유지하며 다음 구역은 직전 클리어로 연다. 4인 자동 플레이 3시드에서 새 4번은 5/12개 라인, 5번은 3/12개 라인이 클리어했다. 이는 사람의 승률이 아니다.

유료 즉시 완충은 **실제 스토어 미연결**이다. 구매 버튼을 비활성으로 표시하고, 서버에 검증 함수가 없으면 충전 요청도 거절한다. 서버 검증 연결점/거래 중복 방지/원자적 지급만 구현했다. 계정 연동·상품/가격·네이티브 구매·스토어 검증/거래 완료 처리는 [결제 연결 문서](ENGINE_BILLING.md)를 따른다. Unity 경로에 엔진 게이트를 연결한 것은 아니다.

[설계·검증 계획](plans/2026-09-23-engine-chapter-one-design.md). 검증: 빌드·콘텐츠·Node 143개, 엔진/챕터 브라우저 18개, 기존 화면 흐름 10개 모두 통과. 가로 시설 정보가 버튼에 가리는 문제도 수정했다. `npm run test:chapter`는 격리된 서버와 가상 시계로 엔진/다섯 맵을 확인한다. 재시작 전 실제 원정은 인메모리여서 소실되며, 동일 원정 영구 복구는 별도다. `.towerdef-data/profiles.json`은 한 개발 서버 프로세스만 사용한다.


## 이전 구현: 큰 글씨·행성 한 장·필요할 때 여는 상세

도현체 제목/주 버튼과 Pretendard 본문/수치를 적용했다. 홈은 장식용 점검 문구를 없애고, 행성은 한 장+화살표+목록으로 바꿨다. 잠긴 행성의 미리보기는 허용하고 출발은 막는다. 유닛 요약은 큰 역할·부족 재료·조립/소모에 집중하고, 판매·파견·수치는 ‘관리·상세’에서 연다. 요약 30dvh와 전장 크기 유지는 그대로다. 과밀 남은 초·시설 위험·보스 제한은 지속적으로 표시한다.

라이터 복귀 자세, 승인된 뽑기 300ms 착지/조립 400ms 체결, 짧은 정상 웨이브 알림을 적용했다. 서버 판정·밸런스·콘텐츠 버전은 유지한다. 폰트 원본/OFL과 자산 대장을 함께 갱신했다. [구현·검증 기록](plans/2026-09-23-mobile-ui-reference-study.md#11-승인-후-구현-기록)을 따른다. 브라우저 시안이며 Unity 이식·실제 아이폰 검증·소비자 비교는 남아 있다. 서버를 다시 시작하면 새 도현체 경로가 반영된다.

## 이전 연구: 인기 모바일 게임 UI와 큰 글씨

[모바일 UI 참조 연구](plans/2026-09-23-mobile-ui-reference-study.md)에 공식 스토어 이미지 12장 검토, 현재 화면 진단, 실제 서체 4종 비교판, 정보 노출·화면·동작의 다음 개편 제안을 정리했다. 도현체 강조+Pretendard 본문을 첫 비교안으로 추천하며, 게임에는 아직 적용하지 않았다. 과밀 남은 시간이 계산되지만 모바일 화면에서 숨겨지는 문제와 작은 보스 제한시간을 우선 수정 대상으로 기록했다. 실제 소비자 조사·경쟁작 모션 측정·휴대폰 검증은 하지 않았다.

## 최신 구현: 생활용품 홈·설명·대표 공격 시안

계획 실행 승인 후 홈을 원정선 안의 생활용품 3기가 장비를 점검하는 장면으로 바꿨다. 본문·Canvas는 로컬 Pretendard v1.3.9를 사용하고 글꼴 라이선스를 포함했다. 홈의 ‘행성 선택’→행성의 ‘출발’을 주요 경로로 삼고, 함께하기는 홈에서도 연다. 배속 설정은 접혀 있지만 일반/연습·보상 여부는 표시한다.

유닛 팝업은 역할·사거리·부족 재료 이름/수량을 먼저 보여주며 최대 30dvh, 전장 크기 유지, 44px 조작 영역을 유지한다. 등급·강화 분류·전체 조립 경로는 상세에서 확인한다. 연구는 조건·비용·실행을 나눴고 강화 문구는 이번 원정에만 적용됨을 명시한다.

기존 점화봇·캔포봇·렌즈봇의 외형만 라이터·헤어드라이어·레이저포인터로 시범 교체했다. 홈/초상/전투가 3자세를 공유한다. 화염·바람·레이저 공격, 실제 냉동 상태 표시, 효과음과 조립 소리를 구분했다. 이름·조합·확률·능력치는 그대로이며 콘텐츠 버전은 `0.7.0-expedition-siege`다. 전체 로스터와 출시 아트 확정은 아니다.

[아트 구현 기록](plans/2026-09-22-art-direction-review-design.md#11-2026-09-22-구현-기록)과 [JEV 준비물](../tools/jev/README.md)을 먼저 읽는다. JEV의 유료 실행은 API 키·격리된 Harness 연결이 준비되지 않아 0회이며, 기존 Playwright baseline과 구분한다. 실제 이용자 선호·iPhone 장시간 성능/음향, Unity 이식은 남아 있다.

검증: Node 112, 브라우저 품질 26, 모바일 7조건·330, 화면 흐름 7, 원정/연구 19, 전투 연출 8, 위치/속성 3조건이 통과했다. 홈 글꼴 로딩·함께하기·동작 줄이기도 확인했다. JEV용 Playwright baseline 9회와 무동작 거부 검증이 통과했으며, 실제 JEV 성공률이나 소비자 조사로 보고하지 않는다. `npm.cmd run dev`로 새 서버를 시작하면 새 폰트·홈 자산 경로가 반영된다.

## 이전 구현: 모바일 홈·행성 선택·시설 방어

`0.7.0-expedition-siege`는 홈 → 행성 선택 → 전투로 화면을 나눴다. 홈에서 출정·연구소·설정·이전 전장 복귀를 열고, 행성 선택에서 목표/패배 조건·배속·협동 방 참가를 확인한다. 상점이나 영구 능력 강화는 아직 추가하지 않았다.

사용자가 표시한 전장 오른쪽 아래에 뽑기를 배치했고, 하단에 분리되어 있던 관리·협동 띠를 없앴다. 로봇·조립·강화 버튼은 왼쪽 아래, 협동 요약은 위쪽에 겹쳐 뜬다. 전장은 HUD 아래 화면 전체를 사용하고 관리/설명 창을 열어도 크기가 유지된다. 30dvh 상자 제한과 44px 조작 영역을 유지했다.

시설 방어는 사용자가 선택한 **도착한 적이 멈춰 계속 공격하는 방식**이다. 첫 행성은 기존 과밀 제한+보스, 두 번째는 채굴기를 보호하며 채굴 완료 시 즉시 클리어, 세 번째는 엔진 보호+보스 처치다. 후속 행성에는 과밀 패배를 중복 적용하지 않는다. 시설 체력 0이면 본인만 패배하고, 시설 파괴가 같은 틱의 완료보다 우선한다. 현재 최대 시간은 8:12 / 26:40 / 30:06이다. 시설 체력·피해량은 시험값이며 새 싱글/협동 시간표는 미적용이다.

검증: 빌드·Node 112검사, 모바일 7조건, 브라우저 품질 26, 위치 3조건, 원정/연구 19, 전투 연출 8, 새 화면 흐름 5크기와 시설 2종이 통과했다. [설계·구현·검증 기록](plans/2026-09-22-mobile-game-flow-design.md)을 먼저 읽는다. 아래는 이전 버전 이력으로, 과거의 하단 띠·보스 필수·자동 전략 통계는 최신 동작으로 해석하지 않는다. Unity 화면 이식과 실제 아이폰 검증은 남아 있다.

## 이전 구현: 랜덤 소환 위치와 속성별 전투

`0.6.0-position-combat`에 **랜덤 빈칸 소환, 선택 재료의 위치를 유지하는 조립, 사거리와 속성별 전투**를 적용했다. 화염은 짧은 사거리·강한 화력, 바람은 스플래시, 냉동은 감속, 레이저는 긴 사거리·단일 공격으로 구분하며 기존 전격도 유지한다. 최종 이름/아트 교체 전의 기존 29종에 시험용 속성을 배정했다.

파견 복귀 칸은 추첨에서 제외하고, 위치 추첨은 유닛 종류 추첨과 분리했다. 도감은 '위치 선택' 후 실제 조립을 실행한다. 설명 상자는 선택한 로봇의 반대쪽에 뜨며 전장 크기는 바뀌지 않는다. 세로 화면은 전장을 회전해 표시하므로 로봇/적 사이의 실제 거리 판정이 화면 비율에 따라 달라지지 않는다. 범위/연쇄 추가 대상은 기존 적 간 경로 거리 조건을 유지한다.

검증: 서버 105, 모바일 7조건·330, 브라우저 품질 26, 위치 전용 브라우저 3조건, 전투 연출 8검사 통과. 장기 보스 체력을 사거리 도입에 맞춰 시험 보정했고, 별도 시드 101~110에서 두 번째/세 번째 행성은 각각 27/40·24/40 개인 라인이 클리어했다. 자동 정책 성과이며 사람의 승률은 아니다. [구현·검증 기록](plans/2026-09-21-position-combat.md)에 수치·범위·후속 작업을 정리했다. Unity 화면 이식과 iPhone 실기 확인은 미완료다.

## 최신 기획 기준: 싱글·협동 시간과 스토리

사용자는 **싱글 5분/10분/15분, 협동 20분/30분을 버틴 뒤 최종 보스 등장**을 기본 설정으로 지정했다. 각 시간은 서로 다른 스테이지/플레이 구성의 기준이며 한 판에서 여러 최종 보스를 순차 소환하는 시각 목록이 아니다. 행성·난도별 배정과 보스전 제한시간은 미정이다. 총 전투 시간에는 실제 보스전 시간이 추가된다.

공동 파견 임무인 스토리는 협동 전용으로 두고, 싱글은 개인 행성 방어·채굴·보스 공략에 집중하는 방향이다. 이번 반영은 기획 문서이며 **현재 코드의 모드 구분·시간·스토리 발생 조건은 아직 변경하지 않았다.** 아래 최대 8:12 / 28:10 / 30:06은 이전 구현 기록으로 읽는다. 새 시간표의 뽑기 횟수·조합 완성률·재화·적 성장 및 스토리 보상/파견 손실을 함께 검증해야 한다. 상세는 [게임 설계](GAME_DESIGN.md)의 모드별 최종 보스 등장 시점 절을 따른다.

## 최신 캐릭터 방향 결정: 생활용품 로봇

사용자는 기본 등급을 라이터·물총·드라이어·제빙기·레이저포인터 같은 친숙한 물건으로 만들고, 상위는 화염방사기·물대포·강풍기·캐논/전차로 발전시키기를 원한다. **물건 자체에 눈과 다리/기계적 특징이 붙는 외형**을 명시적으로 선택했다. 인간형 로봇이 생활용품을 들게 만들지 않는다. [디자인 문서](plans/2026-09-21-household-robots-design.md)에 기준과 시안 후보를 정리했다. 아직 29종 이름·조합식·전투 능력의 최종 교체는 승인/구현되지 않았으며 아래 구현 기록을 이미 바꿨다고 설명하지 않는다.

## 최신 구현: 행성 배경과 로봇 판매

브라우저 전장을 철제 격자 바닥에서 우주가 보이는 야외 채굴지로 바꿨다. 고물 궤도는 크레이터와 먼 행성, 코발트 사구는 푸른 모래 능선과 고리 행성, 성운 심층부는 보랏빛 암반·광맥·성운/위성이다. 가로 화면의 천체는 오른쪽 여백으로 옮겨 HUD/적에게 가려지는 정도를 줄였다. 배경은 기존 지형 캐시에 들어가며 화면 크기나 행성이 바뀔 때만 다시 만든다. 경로·배치 좌표·전투 규칙은 동일하다. 아래 강철 갑판 설명은 이전 표현이다.

유닛 상자 머리글에 ‘판매’를 추가했다. 누르면 같은 상자 안에서 회수 고철과 소모 안내를 확인하고 확정한다. 취소하거나 다른 로봇을 선택하면 판매하지 않는다. 기존 서버의 `salvage`를 사용하며 누적 뽑기 비용의 35%를 내림하여 회수한다. 파견 중 로봇은 판매할 수 없다. 목록 끝의 기존 해체 카드는 제거했다. 이번 배경/판매 화면 변경은 브라우저에 적용했으며 Unity에는 이식하지 않았다.

## 최신 구현: 0.5.0 전투 역할·액션·모바일 전장

사용자는 현재 화면이 게임처럼 느껴지지 않는다며 게임플레이 디자인·애니메이션·액션 개선을 요청했다. 기존 개인 방어·공동 스토리·원정·연구 흐름을 유지하며 다음을 반영했다. 아래 0.4 기록의 ‘모든 공격이 단일 대상’은 이전 상태다.

### 실행·저장·범위

`npm.cmd ci` → `npm.cmd test` → `npm.cmd run dev` 후 `http://127.0.0.1:7351`에서 목적지를 선택하고 **원정 출발**을 누른다. Node 22 이상이다. 브라우저 검사에 필요한 Chromium 경로는 `CHROME_PATH`, 별도 개발 서버 주소는 `PLAYTEST_URL`로 지정한다. `npm.cmd run test:expedition`은 빌드 후 격리된 테스트 서버·임시 저장소를 직접 사용한다.

CLI 서버의 프로필은 `.towerdef-data/profiles.json`, 접근용 인증 정보는 해당 브라우저 localStorage에 보관한다. 원문 프로필 토큰은 서버 파일에 저장하지 않는다. 이 서버 파일은 Git에 포함되지 않으며 집/회사 간 계정 동기화도 아니다. 서버 재시작 후 **프로필은 남지만 진행 중 전투는 복구하지 않는다.** 테스트의 `createDevServer()`는 기본적으로 메모리 저장소를 쓰므로 CLI 영속 저장과 구분한다.

이번 영구 진행은 로컬 HTTP 브라우저 경로에 구현됐다. Nakama는 기존 연습 경로이며 프로필/영구 진행이 이식되지 않았다. 실제 Nakama 서비스, Unity 빌드, 아이폰 화면·성능·발열, 결제·외형 상점·공개 배포는 미검증/미구현이다. Mac mini 보유는 확인됐지만 사양·설치·서명 계정은 확인 전이다.

다음에는 사람이 기본 속도로 플레이하며 중간 조합의 사용 시간, 최종 로봇 완성 시점, 불운 시 전환, 파견으로 인한 방어 손실, 패배 후 재도전 의향을 확인한다. 자동 정책의 승률을 이용자 승률로 쓰지 않는다. 구현 범위와 초기 가정은 [원정 구현 계획](plans/2026-09-21-expedition-progression.md)에 있다.

## 아래는 이전 0.3.0 작업 이력

**현재 콘셉트는 지구를 위한 행성 자원 원정이다.** 자원이 고갈되어 멸망에 가까운 지구에서 원정대를 보내고, 행성에서 폐자원으로 로봇을 조립해 외계 생명체·반란 로봇의 습격을 막으며 채굴을 마친 뒤 떠나는 스테이지 게임을 사용자가 제안했다. 4인 협동과 랜덤·조합·태그 강화 원칙은 유지한다. 고물궤도 정거장은 현재 전투 프로토타입이다.

## 후속 사용자 답변과 다음 구현 기준

- **운과 전환:** 목표 유닛을 못 만들 수도 있게 하고, 다른 조합으로 전환하는 재미를 살린다. 목표·대체 조합의 완성이나 승리를 보장하지 않는다.
- **난도:** 첫 스테이지는 배우며 클리어할 만하게, 이후부터 실패 위험을 크게 높인다. 이 선택은 확정됐으며 구체적인 밸런스 수치는 미정이다.
- **장비:** 사용자에게 Mac mini가 있다. 모델·칩·메모리·macOS와 Unity/Xcode 설치 상태, 서명 계정은 확인 전이다. Mac이 없다고 다시 가정하거나 클라우드 빌드를 유일한 경로로 취급하지 않는다.
- **분위기:** 사용자는 밝고 귀여운 폐품 로봇과 거칠고 묵직한 우주 생존을 모두 원한다. 배경·위협은 거칠게, 주역의 실루엣·표정은 친근하게, 전투의 재질·반동·소리는 묵직하게 배분하는 것이 제작팀의 기본안이다.
- **모바일 몰입:** 30%는 상한이며 고정 점유율이 아니다. 상시 목록·안내를 줄이고, 기능 터치 시 해당 설명과 실행 창을 열며, 이벤트는 전투를 가리지 않는 짧은 알림으로 전달하는 방향이다.

이 후속 답변은 설계·인계 문서에 반영했다. 행성 채굴·탈출 흐름, 스테이지별 난도, 최종 혼합 아트, 평소 접힌 조작 바는 아직 기존 코드에 구현하지 않았다. 아래 테스트 결과는 기존 프로토타입에 대한 것이며 후속 설계의 검증 결과가 아니다.

## 구현된 프로토타입 기준

- 가제는 **폐품로봇 원정대**. 판내 재화는 **고철**, 소환은 **수거**, 진화·합성은 **조립**으로 표시한다.
- 27종 이름과 스토리 3개를 교체했다. 스토리는 6웨이브 조난 신호 구조, 12웨이브 중앙 전력 복구, 18웨이브 탈출 항로 확보다. 규칙·체력·공격력·확률·조합·해금 조건은 이번 변경 대상이 아니다.
- 태그 표시는 `shu/wei/wu` = 리사이클/오비탈/스파크, `infantry/archer/cavalry` = 보행/포탑/궤도, `might/strategy/command` = 동력/연산/제어다. 내부 ID와 `faction/troop/trait`, `summon/combine/gold`는 유지한다.
- 콘텐츠 버전은 `0.3.0-scrap-expedition`이다. 기존 브라우저에 버전 불일치가 나오면 최신 서버로 다시 실행하고 페이지를 새로고침한다.
- 모바일에서는 **상시 노출되는 하단 정보·조작 영역을 가시 화면 높이의 30% 이하**로 제한한다. 상세 조립·도감·긴 안내는 필요할 때 열도록 한다. 실제 소비 재료와 결과 확인은 유지한다.
- 현재 아트는 밝고 귀여운 폐품로봇이며, 초상과 전장 캐릭터가 같은 벡터 원본을 사용한다. 위의 혼합 분위기로 발전시킬 대상이다. 예전 삼국지 PNG는 과거 작업 이력이며 현재 화면의 아트 기준이 아니다.

모바일 하단 조작창과 로봇 선택창은 각각 `30dvh` 높이 안에서 표시하고, 선택창을 열면 기본 조작창을 숨겨 같은 공간을 쓴다. 안전 영역의 여백도 30% 안에 포함한다. 목록은 가로로 탐색하고, 조립 화면은 결과·재료·실행을 우선 표시하며 공격 수치와 다른 사용처는 펼침에 둔다. 동료·스토리는 요약 버튼으로 열고, 설정·협동 상황 같은 별도 창은 필요할 때 확장한다.

구체적인 설계와 검증 기준은 [모바일 설계](plans/2026-09-21-scrap-mobile-design.md)를 참고한다. 아래 이전 검사 통과 수를 이번 변경의 검증 결과로 재사용하지 않는다.

## 직전 작업 기록 — 선택형 진화와 캐주얼 벡터

이 절의 진화·병력 표현과 검사 결과는 이번 세계관 변경 전 작업의 이력이다. 현재 표시 용어는 조립·로봇을 사용한다.

- 화려한 생성 PNG 대신 직접 작성한 가벼운 SVG 캐릭터와 단순한 전장을 사용한다. 초상화·전장 캐릭터가 같은 원본을 공유하며 팔·무기 공격 자세와 다리 보행 포즈가 달라진다. 기존 PNG는 이력용으로 남겼고 자산 대장에서 보관 상태로 표시했다.
- 전장 또는 병력 카드를 누르면 **선택한 유닛에 관련된 진화만** 상세 창에 표시된다. 부족한 재료, 결과 태그, 같이 소모되는 병력과 2기→1기 변화를 확인한다.
- 다른 진화의 재료 사용처와 강화 반영 이론 공격 기여는 펼침 정보로 제공한다. 수치는 소모 재료 전체의 합과 결과를 비교하며, 실전 처치 속도나 최적 경로를 보장하지 않는다.
- 같은 종류가 여러 기여도 클릭한 정확한 개체가 재료에 포함된다. 진화 후 상세 창을 닫고 새 결과 유닛에 선택 표시를 옮긴다.
- 진화 포커스와 최대 2기 파견 대기를 분리했다. 상세 창에서 파견 대기를 지정한 뒤 공동 스토리에서 실행한다. 수동 복귀는 없고 임무 성공·종료에 복귀한다.
- 전체 진화표는 별도 도감에 접어서 보관하며, 도감 자체에서 재료를 자동 선택해 진화시키지 않는다.
- 모바일 상세 창, 글자 대비, 44px 주요 조작 영역을 검증했다. 전투 수치와 조합식은 이번 UI 변경에서 바꾸지 않았다.

핵심 파일: `playtest/app.js`, `playtest/evolution-model.mjs`, `playtest/casual-art.js`, `playtest/battlefield.js`, `playtest/casual-ui.css`. 최종 판정은 여전히 `server/core/index.ts`에 있다.

다음 작업은 아래 순서가 적절하다. 아직 구현 완료된 기능으로 취급하지 않는다.

1. **보스 준비와 패배 복기:** 20~24웨이브 준비 안내, 마지막 병력·강화·남은 적/보스 상태 기록. 정답 투자 버튼이나 승리 보장 표시는 피한다. 첫 강화 시점과 패배 원인 이해도를 확인한다.
2. **소수 유닛의 실제 역할 차이 실험:** 현재 기본 병종은 모두 기초 10 DPS, 영웅은 모두 120 DPS이고 단일 대상 공격이다. 태그 이외의 선택을 만들려면 광역·단일 집중 등 소수 능력을 별도 실험하고 서버 판정·동일 조건 비교를 추가해야 한다. 외형만으로 역할 차이가 생겼다고 하지 않는다.
3. **협동 위험 측정:** 파견자 0·1·2·4명 조건에서 임무 완료 시간, 개인 전장의 최대 적 수·패배를 비교한다. 자동 정책에서 임무가 잘 성공한다는 이유만으로 체력을 즉시 올리지 않는다.

- 전체 회귀 테스트 56개 통과: 전투·접속·중복 요청·렌더러·선택 개체/재료/강화 표시.
