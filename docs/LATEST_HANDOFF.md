# 회사에서 이어가기 — 2026-09-21

## 실행

회사 PC에서 처음 시작한다면:

```powershell
git clone https://github.com/jjhww0522-boop/towerdef.git
cd towerdef
npm ci
npm test
npm run dev
```

이미 복제했다면 먼저 `git status`로 로컬 변경을 확인한 뒤 `git pull --ff-only origin main`을 실행한다. 로컬 수정을 강제로 덮어쓰지 않는다.

브라우저에서 `http://127.0.0.1:7351`을 열고 **새 연습 시작**을 누른다. Node 22 이상이 필요하다. 현재 게임은 로컬 전용 브라우저 연습 버전이며, 실행 서버·진행 중인 방·개인 브라우저 저장 내용은 Git으로 옮겨지지 않는다.

브라우저 자동 검사도 실행하려면 Windows에서 `npx agent-browser install`로 검증용 Chrome을 준비하거나 `CHROME_PATH`를 지정한다. 서버를 켠 상태에서 다른 터미널로 `npm run test:browser`와 `npm run test:quality`를 실행한다.

## 최신 변경

- 화려한 생성 PNG 대신 직접 작성한 가벼운 SVG 캐릭터와 단순한 전장을 사용한다. 초상화·전장 캐릭터가 같은 원본을 공유하며 팔·무기 공격 자세와 다리 보행 포즈가 달라진다. 기존 PNG는 이력용으로 남겼고 자산 대장에서 보관 상태로 표시했다.
- 전장 또는 병력 카드를 누르면 **선택한 유닛에 관련된 진화만** 상세 창에 표시된다. 부족한 재료, 결과 태그, 같이 소모되는 병력과 2기→1기 변화를 확인한다.
- 다른 진화의 재료 사용처와 강화 반영 이론 공격 기여는 펼침 정보로 제공한다. 수치는 소모 재료 전체의 합과 결과를 비교하며, 실전 처치 속도나 최적 경로를 보장하지 않는다.
- 같은 종류가 여러 기여도 클릭한 정확한 개체가 재료에 포함된다. 진화 후 상세 창을 닫고 새 결과 유닛에 선택 표시를 옮긴다.
- 진화 포커스와 최대 2기 파견 대기를 분리했다. 상세 창에서 파견 대기를 지정한 뒤 공동 스토리에서 실행한다. 수동 복귀는 없고 임무 성공·종료에 복귀한다.
- 전체 진화표는 별도 도감에 접어서 보관하며, 도감 자체에서 재료를 자동 선택해 진화시키지 않는다.
- 모바일 상세 창, 글자 대비, 44px 주요 조작 영역을 검증했다. 전투 수치와 조합식은 이번 UI 변경에서 바꾸지 않았다.

핵심 파일: `playtest/app.js`, `playtest/evolution-model.mjs`, `playtest/casual-art.js`, `playtest/battlefield.js`, `playtest/casual-ui.css`. 최종 판정은 여전히 `server/core/index.ts`에 있다.

## 세 페르소나 토의와 후속 제안

아래 토의는 실제 전문가·프로 선수 인터뷰가 아닌 코드 기반 내부 페르소나 검토다. 실제 소비자 참가자는 0명이다.

| 관점 | 최초 주장과 반론 | 합의 |
| --- | --- | --- |
| 게임 설계 | 진화 전후 공격 기여를 보여주자. 숙련 플레이어는 다른 진화 재료를 포기하는 비용이 먼저라고 반박했다. | 소모 병력·결과 태그를 기본 표시하고 숫자·다른 사용처는 펼침에 둔다. |
| 숙련 플레이어 | 선택한 정확한 개체, 사라질 동료, 결과 위치를 통제할 수 있어야 한다. 설계자는 모든 정보를 펼치면 모바일이 복잡해진다고 반박했다. | 개체 소비를 정확히 보장하고 결과를 강조하되 전체 조합 나무는 접는다. 파견 선택과 진화 선택을 분리한다. |
| 개발 | 초상과 전장에 같은 벡터를 쓰고 실제 공격 시점의 자세를 연결하자. 다른 역할은 디테일보다 식별성과 실제 규칙 일치가 먼저라고 반박했다. | 공통 그림·이중 선택링·모션 감소를 유지한다. 아직 없는 탱킹·사거리·광역 능력을 설명에 넣지 않는다. |

토의 원문: [게임 설계](reviews/2026-09-20-game-designer.md), [개발](reviews/2026-09-20-dev-expert.md), [숙련 플레이어](reviews/2026-09-20-pro-player.md).

다음 작업은 아래 순서가 적절하다. 아직 구현 완료된 기능으로 취급하지 않는다.

1. **보스 준비와 패배 복기:** 20~24웨이브 준비 안내, 마지막 병력·강화·남은 적/보스 상태 기록. 정답 투자 버튼이나 승리 보장 표시는 피한다. 첫 강화 시점과 패배 원인 이해도를 확인한다.
2. **소수 유닛의 실제 역할 차이 실험:** 현재 기본 병종은 모두 기초 10 DPS, 영웅은 모두 120 DPS이고 단일 대상 공격이다. 태그 이외의 선택을 만들려면 광역·단일 집중 등 소수 능력을 별도 실험하고 서버 판정·동일 조건 비교를 추가해야 한다. 외형만으로 역할 차이가 생겼다고 하지 않는다.
3. **협동 위험 측정:** 파견자 0·1·2·4명 조건에서 임무 완료 시간, 개인 전장의 최대 적 수·패배를 비교한다. 자동 정책에서 임무가 잘 성공한다는 이유만으로 체력을 즉시 올리지 않는다.

## 검증과 한계

- 전체 회귀 테스트 56개 통과: 전투·접속·중복 요청·렌더러·선택 개체/재료/강화 표시.
- 기본 브라우저 8개 및 선택형 진화 품질 검사 24개 통과 기록. 품질 검사는 실제 서버 조합, 클릭한 개체 포함, 재료 소모, 상세 창 닫힘, 파견 분리, 27종 SVG 디코드와 모바일 조작을 포함한다.
- 상세 실행 보고서·스크린샷은 `artifacts/`에 생성되며 Git에서 제외한다. 회사에서는 위 명령으로 다시 생성할 수 있다.
- 실제 Nakama 런타임, Unity 컴파일, iPhone 빌드·발열·프레임, 실제 이용자 평가는 미검증이다. Unity에는 최신 브라우저 UI/아트를 아직 이식하지 않았다.
- 계정·영구 진행·결제·공개 배포는 수행하지 않았다. 클라우드나 유료 서비스 생성도 없다.
