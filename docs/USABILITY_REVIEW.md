## 전투 정보 개선과 재확인

튜토리얼과 조합 목표 고정은 화면 담당의 작업에 포함돼 있어 중복 개선 항목으로 추가하지 않았다.

| ID | 최초 코드 검토와 가설 | 수정·검증 근거 | 상태 |
| --- | --- | --- | --- |
| U1 — 위험 원인 | 기존 Unity는 적 수·패배 규칙만 표시. 남은 대응 시간이 부족할 수 있음 | 브라우저 코드에 과밀 남은시간·보스 제한시간·실제 패배사유 표시 추가 확인. 첫 웨이브 캡처에는 위험 상태가 없음 | 코드 반영, 위험 장면 확인 대기 |
| U2 — 투자 대상 | 기존 도형은 진영색·이름 중심. 어떤 강화가 적용되는지 다시 찾아야 할 수 있음 | 선택 정보에 이름·등급·3태그·강화 합계 추가. 전투 캡처에서 위 쇠뇌수 [기본], 위/궁병/지략, 강화 +0% 표시 확인 | 데스크톱 선택 정보 확인 |
| U3 — 파견 부담 | 파견으로 개인 방어가 줄고 종료 후 복귀하지만 선택 손익·보상을 놓칠 수 있음 | 전투 캡처에 위 쇠뇌수 파견 예정·개인 방어 제외·복귀 문구 확인. 성공/실패 결과 코드 확인 | 파견 전 안내 확인, 종료 화면 대기 |

U1~U3은 실제 사용자 불만으로 확인된 항목이 아니다. 서버에서 내려오지 않는 정보를 UI에서 추측해 사실처럼 표시하지 않는다. 화면 정보가 보인다는 사실과 이용자가 그 의미를 이해한다는 사실을 구분한다.

## 모바일 코드 검토

최초 `max-width:800px` CSS에서 아래 수치를 확인해 화면 담당에게 전달했다. 다음 수정은 최신 CSS·코드에서 확인했으며 모바일 캡처와 실제 터치는 아직 검증 전이다.

| ID | 최초 확인 | 최소 수정·재확인 | 상태 |
| --- | --- | --- | --- |
| M1 — 작은 판단 정보 | 병력 보조 정보·재료 8px, 안내·스토리 9px, 조합 등급 7px | 재료·안내·스토리 12px, 병력 이름 13px, 조합 이름 14px, 보조 정보 11px. 520px 이하 조합 카드 단일 열 확인 | CSS 반영, 모바일 화면 대기 |
| M2 — 작은 터치 영역 | 파견 높이 약 29.5px, 조합 최소 31px, 방 나가기 약 21px | 파견·조합·목표 고정 44px, 병력 58px, 방 나가기 40px로 확대 확인 | CSS 반영, 실제 경계상자·터치 대기 |
| M3 — 주요 행동 접근 | 전장 → 스토리/동료 → 안내 → 소환/관리 순서로 첫 행동이 아래에 배치 | 모바일 하단에 소환·탭 도구 고정, 바닥 여백 추가 확인. 탭 전환 후 본문이 화면 밖에 남을 수 있어 해당 패널로 이동하는 보완 전달 | 고정 도구 코드 반영, 탭 이동·가림 검사 대기 |

데스크톱 캡처에는 병력·조합·강화·스토리·목표 장수 영역이 분리돼 있다. 작은 문자에 대한 가독성은 사람에게 확인하지 않았고, 캡처 한 장으로 조합·파견·재접속 동작 성공을 주장하지 않는다. Canvas의 축소된 이름 대신 DOM 병력 목록으로 전체 이름과 선택 정보를 제공하는 경로도 실제 좁은 화면에서 확인해야 한다.

## 기록 출처와 저장 표시

피드백 내보내기 출처가 처음에는 인간 입력으로 고정돼 있었다. 자동 폼 테스트도 같은 경로를 사용하므로 사람 자료라고 단정하지 않도록 전달했고, 최신 코드에서 `local-form-entry-unverified`로 변경된 것을 확인했다. `retryIntent`는 재도전 의향이며 실제 재도전 행동 지표와 구분한다. 실제 참가자 여부는 모집·관찰 기록으로 별도 확인한다.

후속 기록에는 화면 크기·배속·콘텐츠 버전, 직접 수행한 조작, 관찰된 결과, 남은 한계를 적는다. 코드 변경만으로 화면 검증 완료라고 하지 않으며, 에이전트 가설을 참가자 발언으로 바꾸지 않는다.
