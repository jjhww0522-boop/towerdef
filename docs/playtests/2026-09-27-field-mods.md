## 동일 입력 정책

솔로 연습, 해당 구역 이전 클리어 조합만 해금, 연구 구매 없음. 매초 높은 조합부터 재료를 확인하고 조립하며, 결과 사거리의 경로·공성 지점 커버리지가 큰 재료 위치를 남긴다. 매초 여유 칸에 1기 소환, 8기 이상일 때 웨이브 경계에서 효율이 큰 기존 분류 강화 1회를 시도한다. 소환·조립·강화는 실제 검증된 액션을 통한다.

**판매·파견·전술은 전 정책 0회**. 기존 일반 시뮬레이터의 만칸→매초 최저 유닛 판매→재소환을 복제하지 않았다. 이 측정은 파견이나 EMP 운용의 성능 비교가 아니다.

| 정책 | 첫 기회 | 둘째 기회 |
| --- | --- | --- |
| 무선택 | 건너뜀 | 건너뜀 |
| 추적 / 분산 / 선제 | 해당 개조 | 같은 개조 유지 |
| 중간 교체 | 분산 노즐 | 본진 냉동 로봇이 있으면 추적 회로, 없으면 선제 센서 |

교체 정책은 비교용 단순 규칙이며 최적 전략이 아니다. 1구역 40/80초, 2구역 80/160초에 즉시 처리한다. 읽는 시간·지연·실수는 시뮬레이션하지 않았다.

- 무선택도 통과하므로 이번 표본에서 개조를 입문 구역의 필수 입력으로 만들지 않았다. 첫 구역 난이도 1/최대 3분, 둘째 난이도 1.5/4분 목표를 유지한다. 높은 승률을 이유로 적을 늘리거나 개조 수치를 키우지 않는다.

## 경제·난수 회귀

- 도구 작성 시작 시점의 `0.11.1` 콘텐츠에서 version/새 fieldMods를 제외한 SHA-256: `56ed70a72165f9d2d08c9759ba6fec4e834d8c8a6547b2c90ed6eb0b6feb35c5`. 새 콘텐츠의 같은 투영이 **완전히 일치**했다. 기존 소환 가중치·유닛·조합·적·고철·보상·시간 수치 변경 없음.
- 매 선택 직전/직후 game 전체를 비교하되 fieldMod와 seq/재전송 기록만 제외했다. 소환 RNG·배치 RNG·보유 고철·유닛·적·투자 행동·개체 ID 등 변화 없음.
- 매 판 `시작 고철 + 틱 수입 - 액션 지출 = 종료 고철` 확인. 200판 판매 0회. 1구역 평균 지출 697.5/잔액 43.5로 전 정책 동일. 2구역 평균 지출 993.5 동일, 잔액 139.8~140.1. 소폭 차이는 종료 전 처치 수 차이로 발생했다.
- 동일 시드의 소환 결과 순서는 이번 전 정책에서 무선택과 같았다. 일반적으로 추가 피해가 처치 시점과 구매 가능 시점을 바꿀 수 있으므로 같은 시드만으로 전체 행동의 인과 동일성을 주장하지 않는다.
- 만칸 시간은 1구역 평균 약 98~102초, 2구역 약 131초. 종료 시점에도 영향을 받는 지표이며 판매 비용 감소나 슬롯 교착 해결의 증거로 사용하지 않는다.

## 조건별 fixture

정상 플레이 승률과 분리된 합성 장면이다. 메모리 게임의 시각·병력·적 HP를 고정하여 한 번의 실제 core tick과 공개 stats를 비교했다. 기존 콘텐츠 수치는 수정하지 않았다.

| 조건 | 기대 / 실제 추가 피해 | 유효 적중 |
| --- | ---: | ---: |
| 추적: 첫 냉동 타격 | 0 / 0 | 0 |
| 추적: 이미 감속된 적, 기본 10 피해 | 1.5 / 1.5 | 1 |
| 추적: 이미 기절 + 과부하, 기본 18 피해 | 4.05 / 4.05 | 1 |
| 분산: 기본 8 폭발, 세 적 | 1.44 / 1.44 | 2 |
| 분산: 기본 34 연쇄, 세 적 | 4.76 / 4.76 | 2 |
| 분산: 적 하나만 존재 | 0 / 0 | 0 |
| 선제: HP 정확히 80%, 기본 18 피해 | 1.8 / 1.8 | 1 |
| 선제: HP 79.9% | 0 / 0 | 0 |
| 선제: 기본 공격만으로 이미 처치(HP 1/1) | 0 / 0 | 0 |
| 선제: 공동 스토리에 파견된 로봇 | 0 / 0 | 0 |

범위/연쇄의 첫 타격은 분산 강화 대상이 아니며, 감속 없는 타격은 추적 대상이 아니다. 세 개조 모두 다른 조건에서 효과가 없을 수 있다는 설명을 유지한다.

## 독립 코드 리뷰

- 검토 범위: core의 `fieldModView`, `performAction`, 재전송 키, `retire`, 본진 피해 처리 및 protocol 공개 projection. 웹은 `sendAction`, 현장개조 표시·병력 설명·개인 결과 참조를 읽었다. 이 범위에서 P0/P1 결함은 발견하지 못했다.
- **P2 해결 확인:** `playtest/app.js:408`의 일정 문구는 개인 종료보다 nextOfferTick 분기를 먼저 처리했다. 2인 게임에서 tick 100에 개인 종료, 동료가 tick 800까지 진행하면 공개 상태는 available=false/nextOfferTick=400인데 문구는 ‘첫 선택까지 0초’가 됐다. 같은 core 상태와 해당 렌더 식으로 재현하여 UI 담당에 전달했다. 담당 수정 후 실제 `renderFieldMods` 소스를 Node VM과 최소 DOM 대역으로 실행해 ‘원정 종료’ 문구와 카운트다운 부재를 확인했다. 실제 개조 선택은 원래 차단되어 전투/경제 결함은 아니었다. 이는 브라우저 렌더링 검증이 아니다.
- 브라우저 터치/스크롤/재전송 시각 검증은 UI 담당의 별도 검사 대상이며 본 보고서의 Node 검증으로 대신하지 않는다. Unity Editor·휴대폰 실행 역시 미검증이다.

## 권고와 다음 사람 검증

조건별 차이가 확인되므로 현재 한 슬롯·두 기회·수치를 유지한다. 입문 구역에서 선택을 의무화하거나 0 피해 기록을 임의 점수로 감추지 않는다. 이후 실제 처음 하는 참가자가 ① 첫 개조 전에 조립을 이해하는지, ② 내 병력에서 어느 조건을 만들 수 있는지 설명하는지, ③ 둘째 선택을 유지/교체로 이해하는지, ④ 선택하지 않고 계속 싸울 수 있음을 아는지 관찰한다. 읽는 중 소환·전술을 놓치는지와 0 피해 결과를 납득하는지도 확인한다. 이 관찰 전에는 재미 향상이나 선택 부담의 적정성을 확정하지 않는다.
