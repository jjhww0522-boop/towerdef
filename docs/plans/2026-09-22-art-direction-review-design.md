# 폰트·설명·연출의 완성도: 20개 페르소나 검토와 개선 제안

날짜: 2026-09-22. 기준: `fb1a7c7`, `0.7.0-expedition-siege`.

상태: **사용자의 계획 실행 승인 후 브라우저 플레이 시안에 반영.** 아래 1–10절은 구현 전 검토·제안이며, 구현 결과와 검증 범위는 마지막 절에 구분한다. 최종 로스터 확정과 실제 이용자 비교는 남아 있다.

## 1. 판단과 근거의 범위

현재 화면에는 기성 요소를 조합한 듯한 인상을 줄 여지가 있다. 원인은 특정 글꼴보다, 비슷한 로봇 외형·장식용 영문·작은 분류 설명·공통 동작이 함께 보이면서 생활용품 원정대라는 개성이 약해지는 데 있다고 본다. 제작 도구를 화면만으로 판별할 수 있다는 뜻은 아니다.

**실제 조사 참가자는 0명이다.** 전문가 13명과 소비자 7명은 서로 다른 우선순위를 검토하기 위한 가상 관점이며, 독립적인 실제 응답이나 시장 통계가 아니다. 표의 낮음/중간/높음은 검증할 가설이다. 이를 합산해 ‘소비자의 몇 %가 AI라고 느낀다’고 표현하지 않는다.

확인한 자료:

- 현재 홈·행성 선택·전투·연구·강화·유닛 설명 화면. 기존 모바일 캡처와 격리된 메모리 프로필로 새로 연 화면을 함께 검토했다. 실제 저장 계정은 변경하지 않았다.
- `playtest/index.html`, `style.css`, `mobile-game.css`, `casual-ui.css`, `app.js`, `battlefield.js`, `casual-art.js`.
- 이번 로컬 자료: `artifacts/art-review-home.png`, `art-review-research.png`, `art-review-stages.png`, `art-review-unit.png`, `art-review-settings.png`, `art-review-upgrades.png`, `art-review-motion-0.png`부터 `-4.png`, `art-review-evidence.json`. 이 경로들은 Git에서 제외된 관찰 자료다.
- 움직임은 소스·브라우저 애니메이션 속성·연속 프레임으로 확인했다. **실시간 영상을 보며 체감을 평가하거나 소리를 직접 청취한 검토는 아니다.** 프레임 수집 간격도 재생 품질 측정값이 아니다.
- 기존 자동 전투 보고서는 30로봇·66적을 데스크톱 헤드리스 브라우저에서 검사했다. 실제 휴대폰의 발열·프레임·타격감·재미를 입증하지 않는다.

확인된 사례:

| 관찰 | 해석과 제한 |
|---|---|
| 최종 DOM 글꼴은 `Bahnschrift`, `Malgun Gothic`, `Apple SD Gothic Neo` 순서이고 Canvas는 `Malgun Gothic`, `system-ui` 순서 | 기기와 표시 위치에 따라 한글·영문·숫자 조합이 달라질 수 있다. 특정 서체를 AI의 증거로 보지 않는다. |
| 유닛 팝업의 역할 줄은 11px, 결과 분류는 10px이며 제목은 15px | 작은 정보의 우선순위 조정이 필요하다. 숨겨진 상세 설명까지 기본 화면에 모두 노출된 것으로 계산하지 않는다. |
| 홈의 장식용 `SCRAP CREW`, 행성의 `SELECT DESTINATION`, 연구의 `EARTH RESEARCH LAB` | 기능을 한글로 다시 설명하므로 공간 대비 효용이 작다. 브랜드 영문을 전부 금지할 필요는 없다. |
| `⌘`가 연구와 조립에 사용됨 | 기능 구별이 약하고 키보드 명령 기호로 읽힐 수 있다. |
| 홈 로봇 그룹은 450ms 투명도·10px 이동, 행성 화면은 같은 문법의 220ms 진입 | 진입 자체는 무난하지만 캐릭터 성격을 드러내는 동작은 아니다. |
| 전투 로봇은 공통 80ms 준비, 230ms까지 사격 자세와 유사한 몸통 변형 사용 | 역할별 작동 원리가 약해질 가능성. 실제 거부감 정도는 동영상·실기기 비교가 필요하다. |
| 등급별 `intensity`가 음향 이벤트에 전달되지만 `combatSound()`에서 사용되지 않음 | 소리 무게 차이를 검토할 지점이다. 실제 청취 없이 음질이 나쁘다고 단정하지 않는다. |

기존 360px 행성 캡처의 ‘이전 행성 탈출 후 개방’ 줄바꿈은 현재 코드에서 이미 ‘이전 행성 클리어’로 줄었다. 미해결 결함으로 재등록하지 않는다. 진입 중 캡처는 투명도가 낮을 수 있으므로 정지 화면 대비 검사는 애니메이션 종료 후 진행한다.

## 2. 가상 패널 20명

## 3. 토론에서 나온 충돌과 정리

### 개성 있는 글꼴인가, 잘 읽히는 글꼴인가

- 18: “로고는 장난감처럼 기억났으면 좋겠다.”
- 2·17: “재료명과 숫자까지 장식하면 판단이 느려진다.”
- 20: “서체만 특이해지고 장면이 같으면 인상도 그대로다.”
- 제안: 로고에만 별도 조형을 주고 본문은 통일한다. 이름·부족 수량·다음 행동을 먼저 읽히게 한다.

### 홈의 생동감인가, 빠른 시작인가

- 7·8·18: “라이터가 뚜껑을 열거나 드라이어가 팬을 점검하면 기억할 수 있다.”
- 11·16: “모두 계속 움직이거나 매번 기다리게 하면 피곤하다.”
- 1: “장면의 이유가 있어야지, 떠다니는 장식은 더 필요하지 않다.”
- 제안: 짧고 드문 준비 행동을 한 번에 하나만 보여준다. 출발 입력은 항상 가능하고, 배경은 조용하게 둔다.

### 설명을 줄일 것인가, 전략 정보를 남길 것인가

- 15: “지금 조립하려면 무엇이 부족한지 먼저 알고 싶다.”
- 14: “나중에 뭘 만들지 보려면 전체 경로도 필요하다.”
- 5·12: “첫 화면의 정보 우선순위와 상세 접근을 함께 설계해야 한다.”
- 제안: 기본 요약→선택한 조립의 상세→전체 경로로 나눈다. 기존 경로 기능을 숨겨 찾을 수 없게 하거나 설명을 10px로 우겨넣지 않는다.

### 조립의 보상감인가, 전투의 판독성인가

- 9·10: “체결 뒤 시동이 걸리는 순간은 확실해야 한다.”
- 12·16: “합성할 때마다 전투를 가리거나 멈추면 불편하다.”
- 제안: 선택 유닛 자리에서 짧게 체결·시동·완성 이름을 표시한다. 반복 조립은 간결하게, 특별한 완성만 조금 더 강조한다. 서버 판정·실제 공격 횟수·재화 소모는 바꾸지 않는다.

### 협동의 발견성인가, 홈의 단순함인가

- 19: “친구와 할 수 있다는 것은 시작 전에 알아야 한다.”
- 3·15: “모드와 방 관련 버튼을 전부 늘어놓고 싶지는 않다.”
- 제안: 현재 큰 주 버튼을 유지하며 기존 함께하기 연결을 보조 동선으로 검토한다. 이번 계획을 싱글/협동 규칙 분리 구현으로 확대하지 않는다.

| A. 글꼴·문구·간격만 정리 | 가장 빨리 가독성과 일관성을 개선 | 캐릭터와 홈의 고유 장면은 그대로 | 첫 작업으로 채택 |
| B. 생활용품 원정대의 장면까지 통일 | 세계관·캐릭터·버튼·동작이 연결됨 | 대표 캐릭터와 모션 샘플 제작 필요 | **최종 추천. A부터 시작해 좁은 범위로 검증** |
| C. 전체 픽셀 아트 또는 강한 수작업 화풍으로 전환 | 명확한 시각적 변화 | 작은 한글·다양한 해상도 대응, 전체 자산 재작업. 현재 문제를 자동 해결하지 않음 | 현재는 보류 |

B의 방향 문장: **“고갈된 지구에서 출발한 생활용품 로봇들이 낡은 원정선을 고쳐 타고, 낯선 행성에서 자원을 확보한다.”**

우주는 넓고 조용하게, 원정선과 로봇은 작고 익살스럽게 표현한다. 배경의 위험과 캐릭터의 친근함을 함께 살린다. 생활용품 몸체가 주인공이며, 사람형 로봇에게 물건을 들려주는 방식으로 되돌리지 않는다.

## 5. 화면별 제안

### 홈

- 창밖 행성과 작은 원정선 작업 공간을 배경으로 한다. 작업실이 전체를 덮어 다시 공장처럼 보이지 않게 우주가 읽히는 면적을 확보한다.
- 로봇 3기를 전시하는 대신 대표 1기가 출발 장비를 확인하는 장면을 중심에 둔다. 동료는 보조로 배치하고 실제 버튼과 혼동되는 장식은 피한다.
- 큰 주 행동 하나, 연구·함께하기·설정은 기존 기능의 보조 동선으로 정돈한다. 없는 상점·영구 능력 강화 버튼을 추가하지 않는다.
- 장식 영문은 줄이고 로고에 개성을 집중한다. 슬로건은 짧은 한 줄까지만 유지한다. 테스트용 ‘플레이 의견’은 설정에서도 접근되므로 홈 전면 배치의 필요성을 재검토한다.
- 홈의 ‘행성 선택’과 선택 후 ‘출발’을 구분하는 문구 시안을 비교한다. 연출을 기다려야 누를 수 있는 출발 버튼은 만들지 않는다.

### 행성 선택

- 행성 이름, 목표, 실패 조건, 시간, 출발 순으로 읽는다. 행성별 아이콘은 순환 방어·채굴기·엔진으로 목적을 돕되 짧은 글을 함께 표시한다.
- 배속/연습 옵션은 기존 선택값과 저장 여부를 유지한 채 보조 설정으로 접는다. 연습 선택 상태를 숨겨 보상 여부를 오해하게 하지 않는다.
- 잠긴 목적지는 잠김 표시와 조건을 구별해 표현한다. 카드 전체를 흐리게 해서 조건까지 읽기 어렵게 하지 않는다.
- 이번 계획에서 기존 시간·패배 조건을 바꾸지 않는다. 시간 표기는 실제 콘텐츠 값에서 가져온다.

### 유닛·조립·강화 설명

- 전장 크기를 유지하는 오버레이와 화면 높이 30% 제한을 유지한다. 글이 길면 같은 패널 안에서 단계적으로 열거나 스크롤한다. 상세를 눌러도 전투와 뽑기 접근을 방해하지 않도록 검증한다.
- 기본 유닛 설명은 이름 → 역할/사거리 → 다음 조립과 부족 재료 → 행동 순서로 정리한다.
- 강화 선택은 실제 강화 대상과 적용되는 보유 로봇을 보여준다. 현재 강화는 리사이클·오비탈 등의 태그를 사용하므로, 이를 근거 없이 ‘화염 강화’처럼 다른 시스템으로 바꾸어 적지 않는다. 내부 표현인 ‘태그 강화’ 제목을 쉽게 바꾸되 실제 범위는 정확히 남긴다.
- 수치·다른 사용처·전체 조합 경로는 추가 열람으로 남긴다. 조립하면 선택한 유닛 위치를 유지한다는 점과 재료 소모를 실행 전에 확인할 수 있어야 한다.
- 판매에는 반환량, 조립에는 필요 수량, 연구에는 적용 시점을 표시한다. 설명과 버튼 모두 같은 서버 데이터에서 실제 값을 사용한다.

### 연구·결과·설정·사건 안내

- 연구: 새 조합식이 무엇을 열어주는지, 조건과 비용이 무엇인지 우선한다. 영구 해금과 이번 판 재료 획득을 분명히 구별한다.
- 결과: 성공/실패와 직접 원인을 먼저, 획득 보상과 다음 행동을 뒤에 둔다. 세계관 문장은 보조로 배치한다.
- 설정: 효과음·동작 줄이기 등 결과가 명확한 짧은 이름을 쓴다. 제작 과정이나 ‘실제’ 같은 불필요한 수식어를 줄인다.
- 전투 사건: 시설 피해·보스·조립 완료를 중요도에 따라 다르게 알린다. 모든 사건에 큰 팝업을 띄우지 않고, 중요한 시설 위기는 세계관 대사보다 상태가 먼저 읽히게 한다.

## 6. 문구 시안

현재 이름은 예시다. 최종 유닛 개명이나 조합식 변경을 확정하지 않는다.

| 현재 | 제안 | 주의 |
|---|---|---|
| 홈 `출정`, 다음 화면 `원정 출발` | 홈 `행성 선택`, 다음 화면 `출발` | 단계 차이를 명확히. 게임 분위기와 이해도를 실제 비교 |
| `SELECT DESTINATION` + `어디로 떠날까?` | `행성 선택` 한 줄 | 중복 장식 제거 |
| `로봇 뽑기로 첫 로봇을 만나세요.` | `로봇을 뽑아 방어를 시작하세요.` | 행동과 목적 연결 |
| `재료 부족` | `궤도봇 1기 필요` + 비활성 `조립` 버튼 | 이름과 수량은 실제 부족분. 여러 재료면 모두 확인 가능 |
| `개조 · 스파크/포탑/동력` | 역할 한 줄 우선, 분류는 상세 | 강화 적용을 판단할 수 있는 분류 정보는 유지 |
| `태그 강화` | `로봇 강화` → 선택한 강화의 대상·효과 | 영구 강화로 오해하지 않게 이번 원정 적용 여부를 명시 |
| 연구 버튼 `탐사 필요` | 조건 `고물 궤도 클리어 후 연구` + 비활성 `연구` | 스테이지 조건과 연구 비용을 따로 설명 |
| 연구의 긴 공통 설명 | `조합식은 계속 유지돼요. 재료는 매 원정에서 모아요.` | 실제 해금·적용 시점과 일치하도록 확인 |
| `실제 사격·폭발·조립의 효과음을 들려줍니다.` | `공격·조립 효과음` | 설정 효과만 간결하게 |
| `자원과 함께, 지구로.` | 제목 `원정 성공`, 보조 `자원을 싣고 귀환합니다.` | 성공이 확인된 경우에만 |
| `이번 원정은 여기까지.` | `원정 실패` + 실제 원인 예: `채굴기가 파괴됐어요.` | 시설·과밀·보스 시간 초과별 실제 원인 |

## 7. 글꼴·아이콘·모션 기준안

### 글꼴과 아이콘

- 본문은 하나의 한글 지원 글꼴과 3개 안팎의 굵기로 정돈한다. 후보는 Pretendard를 우선 시안으로 비교한다. 글꼴 이름 자체가 개성이나 품질을 보장하지는 않는다.
- Pretendard는 공식 저장소에서 교차 플랫폼용 글꼴과 굵기를 제공하며 라이선스는 SIL OFL 1.1이다. 실제 도입 시 원본 라이선스·저작권 고지를 함께 보관한다. 이번에는 다운로드하거나 적용하지 않았다. [공식 저장소](https://github.com/orioncactus/pretendard), [라이선스](https://github.com/orioncactus/pretendard/blob/main/LICENSE).
- DOM과 Canvas가 같은 본문·숫자 규칙을 사용하게 하고, 로딩 후에도 글자 폭과 위치가 안정적인지 확인한다. 모바일 앱의 오프라인 사용을 고려해 외부 CDN에만 의존하는 구성은 피한다.
- 시안 시작값: 화면 제목 22–28px, 주요 버튼 16–18px, 본문·역할·재료 14–16px, 중요도가 낮은 보조 정보 12–13px. 이는 표준의 최소 글자 크기 주장이 아니라 실제 폰에서 조정할 초기안이다.
- 본문은 넉넉한 줄 간격, 자연스러운 한글 자간을 사용하고 좁은 공간을 자간 압축으로 해결하지 않는다. 수량과 비용은 자리 변화가 덜한 숫자 표현을 검토한다.
- 일반 필수 설명의 대비 목표는 4.5:1 이상. WCAG는 일반 텍스트 4.5:1, 큰 텍스트 3:1을 제시한다. 비활성 UI의 예외가 있더라도 해금 조건은 읽을 수 있도록 별도로 설계한다. [W3C 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- 로봇·조립·강화·연구·설정에 작은 전용 아이콘을 같은 선과 면 규칙으로 만든다. 짧은 기능 이름도 함께 남긴다. 로고와 배경의 재질감은 본문 글자에 적용하지 않는다.

### 움직임과 소리

대표 후보는 라이터·헤어드라이어·레이저포인터의 3종이다. 사용자에게 이미 제시된 생활용품 방향을 보여주는 샘플이며, 최종 이름·등급·조합식은 별도 확정한다. 냉동 표현도 공격 효과 기준에서 함께 검토한다.

| 대상 | 움직임의 이유 | 효과와 소리의 방향 |
|---|---|---|
| 라이터 / 짧은 사거리 화염 | 뚜껑·점화 장치가 작동하고 작은 몸체가 버팀 | 짧고 넓은 불꽃, 순간적인 점화음. 실제 피해 대상 수보다 넓게 맞는 것으로 오해시키지 않음 |
| 헤어드라이어 / 바람 | 팬이 돌고 몸체가 뒤로 버팀 | 방향성 있는 압력 표현과 짧은 바람 소리. 밀치기가 없다면 적이 밀리는 연출을 추가하지 않음 |
| 레이저포인터 / 긴 사거리 단일 공격 | 렌즈가 조준한 뒤 짧게 발광 | 가는 광선과 명확한 단일 피격. 직선 위 모든 적을 관통해 때리는 것처럼 보이지 않게 함 |
| 냉동 효과 | 맞은 적의 표면에 서리가 생김 | 감속 상태와 지속이 읽히는 표식. 실제로 멈추지 않는 적을 완전 결빙으로 표현하지 않음 |
| 조립 | 선택 유닛 자리에 재료가 결합하고 시동 | 짧은 체결음→시동음→이름. 입력과 전투는 계속 가능 |
| 홈 | 출발 준비 중 장비를 점검 | 한 번에 하나의 짧은 행동. 상시 둥실거림·카메라 이동·반짝임은 늘리지 않음 |

버튼 반응은 즉시 보이고 메뉴 전환은 짧게 한다. 시안에서는 일반 조립의 국소 연출을 약 0.4초부터 비교하되, 공격 시간·서버 판정을 지연시키거나 0.4초를 새 입력 대기 시간으로 만들지 않는다. 반복 빈도와 실제 폰 체감을 보고 조정한다.

동작 줄이기에서는 장식 이동·찌그러짐을 없애고 성공·피격·시설 위기를 정적인 표시로 보존한다. 비필수 상호작용 애니메이션을 끌 수 있도록 하는 방향은 W3C의 별도 AAA 항목을 참고한다. 이는 프로젝트 전체가 WCAG AAA를 준수한다는 주장이 아니다. [W3C 동작 안내](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html).

## 8. 실행 순서와 완료 기준

기간은 아직 산정하지 않는다. 대표 캐릭터 제작 방식과 실기기 범위가 정해진 뒤 추정한다. 현재 계획은 다음 작업의 범위와 통과 기준을 정하는 데 목적이 있다.

| 순서 | 산출물·범위 | 담당 관점 | 완료 판단 |
|---|---|---|---|
| 1. 설명·글꼴 정리 | 문구 목록, 본문 규칙, 주요 아이콘 시안, 유닛/강화/연구 팝업 | 2·3·4·5·6·12 | 작은 화면에서 부족 재료·비용·적용 대상을 읽고 행동할 수 있음. 전체 경로도 접근 가능 |
| 2. 대표 장면 | 홈 정지 시안 2개와 생활용품 3종 실루엣·성격표 | 1·7·13·18 | 물건과 게임의 핵심 행동을 설명 없이 유추 가능한지 비교. 목록 확정 전 전체 로스터 제작하지 않음 |
| 3. 짧은 플레이 시안 | 대표 공격 3종, 냉동 상태, 뽑기·조립·시설 경고·화면 전환 | 8·9·10·11·12 | 연출이 실제 판정과 일치하고 연속 조작을 막지 않음. 소리를 꺼도 역할과 위기를 파악 |
| 4. 실제 이용자 비교 | 이전/개선 시안, 폰 플레이, 이해·선호·불편 기록 | 3·5·13 및 실제 참가자 | 정보 이해와 조작에서 악화가 없고, 구체적인 개성·완성도 개선 이유가 관찰됨 |
| 5. 채택안 반영 | 선택된 홈·설명·공통 연출만 제품 반영 | 개발·QA | 회귀 검사·실기기 확인 후 커밋과 푸시. 전체 자산 확대는 별도 단계 |

이번 범위에서 유지할 것: 홈→행성→전투 흐름, 전장 안 뽑기, 랜덤 빈 위치 소환, 선택 위치 조립, 개인 방어와 협동 스토리의 역할 구분, 재화·확률·강화·해금 규칙. 사용자 제안 중 아직 구현되지 않은 싱글/협동 시간표·뽑기 개편을 문구 수정만으로 구현된 것처럼 표시하지 않는다.

## 9. 실제 검증 계획

### 소규모 사용성 비교

초보·랜덤디펜스 경험자·협동 선호자가 섞인 실제 참가자 8–12명 정도로 먼저 문제를 찾는다. 이 수는 탐색 제안이며 시장 대표 표본이나 성공률 추정 근거가 아니다. 참여 동의 후 모집하고, 이번 검토에서 모집이나 외부 연락은 하지 않았다.

1. 제작 방식이나 ‘AI’라는 말을 먼저 알려주지 않는다. 현재안과 개선안의 제시 순서를 나눠 순서 효과를 줄인다.
2. 홈을 짧게 보여주고 ‘무슨 게임으로 보이는가’, ‘무엇을 먼저 누르겠는가’, ‘기억나는 것은 무엇인가’를 묻는다.
3. 행성 출발, 첫 뽑기, 부족 재료 찾기, 강화 대상 확인, 연구 효과 설명의 과제를 준다. 막힌 지점·오해·소요 시간을 기록한다.
4. 같은 전투 장면을 소리 있음/없음, 필요하면 동작 줄이기로 비교한다. 공격 역할·시설 위험·조립 완료를 알아차리는지 확인한다.
5. 자유 의견을 받은 뒤 ‘자동 생성되거나 기성품을 조합한 듯한 부분이 있는가’, ‘그것 때문에 계속하기 싫어지는가’, ‘어느 장면 때문인가’를 별도로 묻는다. ‘AI 같다’와 ‘싫다’를 하나의 점수로 합치지 않는다.
6. 과반 선호만으로 채택하지 않는다. 반복되는 이해 오류나 읽기 실패가 있으면 먼저 수정한다. 결과는 실제 인원과 발언·과제 수행을 함께 기록한다.

### 구현 후 회귀 확인

- 세로 360×640·390×844, 가로 667×375·844×390 및 데스크톱. 실제 iPhone Safari와 안드로이드 휴대폰도 구분해서 확인한다. Unity/네이티브 화면은 해당 구현 시 별도 검증한다.
- 팝업을 열어도 전장 영역·전투 좌표·사거리가 변하지 않고, 30% 요약 패널과 최소 44px 조작 영역을 유지한다. 짧은 가로 화면에서는 글자 축소 대신 상세 단계/스크롤을 검증한다.
- 유닛을 선택하고 조립/판매한 뒤 표시되는 부족분·반환량·상태가 실제 서버 결과와 일치한다. 강화가 다른 대상으로 오해되지 않는다.
- 연속 뽑기·조립 중 화면 가림과 입력 누락이 없고, 실제 피해 없이 피격 효과가 생기거나 중복 사운드가 재생되지 않는다.
- 동작 줄이기·무음에서도 보스/시설 위기와 조립 완료를 식별한다. 강화/연구의 적용 범위와 저장 여부를 짧은 문구로 이해할 수 있다.
- 같은 기기·조건에서 개선 전후를 비교하고, 밀집 전투와 20–30분 실행의 프레임·발열·반응을 확인한다. 헤드리스 프레임 값을 실제 폰 성능으로 보고하지 않는다.
- 구현 시 관련 기존 검사 `test:flow`, `test:mobile`, `test:expedition`, `test:combat`, `test:position`을 변경 범위에 맞게 실행한다. 이번 문서 작업에서는 게임 변경이 없어 전체 게임 테스트를 재실행하지 않았다.

## 10. 다음 결정

추천 출발점은 **A로 읽기와 의미를 정리한 뒤, B의 홈 장면·대표 3종만 만들어 비교하는 것**이다. 본문 서체 시안, 대표 생활용품 3종의 확정, 두 홈 시안 중 채택은 실제 시안을 보며 결정한다. 전체 로스터·새 상점·새 모드는 이 계획의 선행 조건이 아니다.

추가 요청에 따른 [JEV Ultrafast 도입 검토](2026-09-22-jev-evaluation.md)는 메뉴·설명 탐색을 보조하는 별도 실험안이다. 시각·감성 평가나 실제 이용자 검증의 대체 수단으로 삼지 않는다.

## 11. 2026-09-22 구현 기록

사용자의 ‘계획에 따라 작업진행’ 승인으로 A의 읽기·의미 정리와 B의 홈 장면·대표 3종을 브라우저 플레이 시안에 구현했다. 콘텐츠 버전은 `0.7.0-expedition-siege`이며 이번 변경은 서버 전투·경제·뽑기 확률·조합식·유닛 이름을 변경하지 않는다.

| 적용 부분 | 실제 변경 |
|---|---|
| 글꼴·아이콘 | Pretendard Variable v1.3.9를 로컬 WOFF2로 포함하고 DOM·Canvas 본문을 맞췄다. OFL 원문과 출처를 함께 보관했다. 로봇·조립·강화·연구·설정 등에 공통 선 규칙의 SVG 아이콘을 적용했다. |
| 홈·행성 | 원정선 갑판에서 출발을 준비하는 3기, 창밖 행성, 장비 점검 동작으로 홈을 구성했다. 주요 버튼은 ‘행성 선택’→‘출발’. 함께하기를 홈에서도 열 수 있다. 연습 배속은 ‘원정 설정’에 접되 현재 배속·보상 여부는 항상 표시한다. |
| 설명 | 부족 재료 이름·수량, 연구 조건·비용, 이번 원정에만 적용되는 강화 범위를 구분했다. 유닛 역할·사거리를 먼저 보여주고 등급·분류·상세 계산·전체 조립 경로는 펼쳐 볼 수 있게 했다. |
| 대표 외형 | 기존 점화봇(`wu_archer`)은 라이터, 캔포봇(`shu_archer`)은 헤어드라이어, 렌즈봇(`wei_archer`)은 레이저포인터 몸체로 만들었다. 각 3자세를 홈·초상·전투에서 공유한다. 나머지 로스터의 이름·외형을 확정하거나 전체 교체하지 않았다. |
| 공격·조립 | 화염의 점화·불꽃, 바람의 팬·압력, 레이저의 짧은 광선을 구분했다. 냉동 표시는 서버 감속 상태를 따른다. 공통 몸통 늘이기를 줄이고 부품 움직임을 살렸다. 속성·이벤트 강도에 따른 효과음과 조립의 체결·시동 소리를 구현했다. |
| 모바일 제약 | 전장 내부 뽑기·관리 버튼과 선택 팝업을 유지한다. 유닛 팝업은 최대 30dvh이며 전장 크기를 바꾸지 않는다. 짧은 가로 화면의 배속 옵션 겹침, 닫기 버튼 잘림, 조립 재료 줄 잘림을 수정했다. |

테스트 도구도 접힌 원정 설정을 실제 클릭으로 열고 닫도록 수정했다. 캔버스 선택 검사는 팝업에 가려진 좌표를 탭하는 대신 실제 노출된 다른 로봇을 찾은 뒤 물리적인 터치 입력과 서버·선택 상태를 확인한다. 강제 클릭으로 가림 문제를 무시하지 않는다.

원정 통합 검사의 기존 보스 완료 픽스처는 출현 직후 한 틱에 처치된다고 가정했다. 랜덤 배치에서는 사거리 밖일 수 있어, 보스 제한 시간 안에서 실제 이동·공격·결과 확정을 기다리도록 수정했다. 게임 코어를 바꾸거나 성공 상태를 직접 주입하지 않았다.
