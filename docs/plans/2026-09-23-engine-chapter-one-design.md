# 엔진과 챕터 1 구현 계획

승인: 엔진 최대 5개, 새 원정 참가당 1개 소모, 30분마다 1개 회복, 유료 즉시 충전. 같은 고물 행성에 다섯 스테이지.

## 엔진
- 최초 5개. 일반/배속 연습 모두 새 참가에 1개 사용. 실패/중도 이탈 환급 없음.
- 같은 원정 재접속/재시도 무료. 거절된 입장은 차감 없음.
- 서버 시계로 오프라인 회복. 가득 찬 동안 회복 시간을 비축하지 않음.
- 기존 저장 기록은 유지하고 엔진 필드가 없는 계정만 5개로 시작.
- 유료 상품은 엔진 즉시 완충. 서버에서 검증한 거래만 적용, 거래 재사용 차단.
- 스토어 정보가 없어 실제 결제는 비활성. 연결 전임을 화면에 표시. 검증 연결점과 원자적 지급만 구현하며 실제 결제 완료로 보고하지 않음.
- 서버 재시작 시 기존 인메모리 원정은 사라짐. 살아 있는 동일 원정 재접속만 무료이며 원정 영구 복구는 별도 작업.

## 챕터 1
- 기존 1~3의 식별자/시간/목표/연구 기록 유지. 4~5 추가.
- 착륙 지대, 채굴장, 엔진 기지, 좁은 협곡, 탈출항. 공통 행성 배경과 서로 다른 경로/배치 위치/수.
- 서버와 Canvas는 같은 geometry 사용. 랜덤 소환/선택 자리 조립 유지. 확률과 조합식 변경 없음.
- 직전 스테이지 클리어 시 다음 해금. 새 4/5는 10분/15분 방어 후 보스. 난이도는 기존 수치 기반 초기값.

## 검증
1. 저장/회복: 30분 경계, 연속 차감, 오프라인, 최대치, 기존 데이터, 저장 실패.
2. API: 입장 실패, 재접속, 중복 요청, 위조 결제, 검증 거래 재전송/타 계정 재사용.
3. 맵: 슬롯/경로 차이, 서버/화면 좌표, 사거리, 조립 위치, 시설 정지 공격.
4. 모바일 홈→선택→입장, 엔진 부족/회복, 5개 맵 캡처. 빌드/회귀 검사 후 푸시.

참고: [Google 결제 보안](https://developer.android.com/google/play/billing/security), [Apple StoreKit](https://developer.apple.com/documentation/storekit/in-app-purchase).

## 구현 결과와 검증

- 엔진 저장/API/홈·스테이지 표시/충전 안내를 구현했다. 프로필 공개 응답에는 잔액·최대치·회복 시각만 포함하고 원정/구매 내부 기록은 노출하지 않는다.
- 기존 1~3 식별자·목표·시간·연구 기록을 유지했고 4~5를 추가했다. 배치 수는 30/28/26/22/24다.
- 새 보스 체력은 자동 플레이를 확인해 4번 200,000, 5번 300,000으로 보정했다. 동일 4인·시드 1/2/3·기본 조합식 봇의 클리어 라인은 각각 5/12, 3/12다. 사람의 클리어율이 아니다.
- 작은 가로 화면에서 시설 정보가 조작 버튼에 가리는 문제를 발견해 시설 왼쪽 여백에 이름·체력·공격 수를 배치했다. 시설 위치/공격 판정은 유지했다.
- `npm.cmd test`: 빌드·콘텐츠 검증 및 **143/143** 통과. 엔진 저장소/API 검사 19개를 포함한다. 시간 경계, 저장 실패 원자성, 기존 기록, 재접속/입장 거절, 결제 위조/중복/다른 계정 재사용을 확인했다.
- `npm run test:chapter`: **18개 시나리오** 통과. 360×640·390×844·667×375에서 엔진 소진→입장 차단→서버 시간 회복→재입장, 다섯 맵의 실제 뽑기·슬롯 수·전장 크기 유지·시설/버튼 겹침을 확인했다. JavaScript 오류 0건. 보고서는 artifacts/engine-chapter-report.json이다.
- `npm run test:flow`: **10개 시나리오** 통과. 기존 홈/스테이지/전투/연구/귀환/시설 방어/과밀 경고 흐름을 유지했다.
- 홈·충전·스테이지·협곡과 가로 시설 화면의 캡처를 검토했다. 가로 뽑기 버튼이 경로 모서리 일부를 덮는 기존 배치는 남아 있다.
- 실제 결제/IAP, Unity 엔진 게이트 이식, 실제 휴대폰 성능과 사람의 난이도 검증은 완료하지 않았다. [결제 연결 문서](../ENGINE_BILLING.md)를 따른다.
