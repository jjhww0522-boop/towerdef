# 원랜디 참고: 읽히는 전장과 솔로·협동 분리

2026-09-29. 사용자는 인터넷 조사부터 우리 모바일 스테이지 게임에 맞춘 대규모 구현·검증까지 자율 진행을 요청했다. 기준 브랜치는 `feat/reignition-overhaul`, 시작 커밋은 `49a211d`다.

## 참고와 선택

공개 배포 공지와 최근 플레이 공략에서 확인되는 ORDR 2.323을 최근 운영 구조의 기준으로 삼는다. `ordr.kr`는 개인 조합 도우미이며 제작팀 공식 사이트로 취급하지 않는다. 버전별 비교 이용자·평점 표본이 없어 ‘가장 인기 있는 버전’은 단정하지 않는다. 출처와 관측/추정/미확인 항목은 [조사 기록](../reference/2026-09-29-ord-research.md)에 남긴다.

세 가지 접근을 비교했다. 65라운드 장기전을 옮기면 짧은 행성 탐험과 충돌한다. 외형만 바꾸면 조합 계획과 파견의 판단이 빠진다. 따라서 개인 방어·역할별 조립·공세 예고·공동 임무의 기회비용을 우리 스테이지 길이에 맞춰 적용한다. 외부 캐릭터·지도·UI 자산을 가져오지 않고 기존 우주/가전 로봇 아트를 사용한다.

## 구현 계약

1. 서버가 `mode: solo | coop`를 보유한다. 개인전은 한 명만 입장하고 공동 스토리/파견이 없다. 협동전은 한 명이 남아도 협동전이며 개인 라인 공격은 서로 간섭하지 않는다. 공동 스토리 성공 보상은 기존 생존자 공통 보상으로 유지한다. 기존 요청의 mode 생략은 coop 호환, 새 웹/모바일 클라이언트는 항상 명시한다. 재접속과 잘못된 모드 입장에는 엔진 추가 차감을 방지한다.
2. 기존 다섯 맵의 서버 좌표·사거리·경로·슬롯·몹 속도와 생성 총량을 보존하면서 화면 투영을 등방 배율로 통일한다. 긴 맵은 화면 방향에 맞춰 돌려 배치 간격을 확보한다. 원형 사거리와 실제 판정을 일치시키며 로봇 크기는 인접 칸 간격을 넘지 않게 한다. 작은 화면은 로봇 목록에서도 정확히 선택할 수 있다.
3. 적의 실제 공격·체력은 서버 판정을 따른다. 같은 위치의 군집은 길의 접선/법선 방향을 이용해 시각적으로 구분하고 시설 앞 적체 수를 명시한다. 표시 대형을 서버 충돌이나 별도 생성 수치로 오해하지 않게 문서화한다.
4. 홈에서 개인/협동 출발을 명확히 나누고 전장에는 현재 목표, 다음 공세, 실제 재료 기준 조립 가능 상태를 짧게 제공한다. 협동 기능은 협동에서만 노출한다. 로봇 선택→조립/판매 확인 흐름과 전장 비율 유지, 작은 화면의 실제 터치를 검증한다.
5. 기존 6속성 25종·24개 동일 3기 조합, 무작위 빈칸 뽑기·기준 자리 조립, 해금·엔진·저장 규칙을 유지한다. 1구역 난도1/최대3분, 2구역 난도1.5/4분을 보존한다. 원랜디의 장시간 성장 및 고급 유닛을 초반 필수 조건으로 추가하지 않는다.

## 화면 방향

- 시각 기조: 어두운 행성 지면 위에 밝은 가전 로봇, 또렷한 길과 배치 받침대가 먼저 읽히는 소형 전장.
- 정보 순서: 전장 → 현재 위험/목표 → 뽑기·조립 → 필요할 때 여는 상세. 고정 설명 패널은 늘리지 않는다.
- 동작: 기존 실제 공격 반동·조립 체결을 유지하고 조립 가능한 로봇 강조와 적 대형 이동을 추가한다. 움직임 줄이기 설정에서는 장식 움직임을 억제한다.

## 분담과 검증

- 기획: 외부 근거와 비교표. 서버: 모드/입장/보상 계약. 클라이언트: 화면 흐름·모바일 DTO/UI. 대장: 전장 투영·군집 가독성·통합. 독립 QA: 핵심 입력·개인 격리·협동·반복 입장 검증.
- 변경 전/후 360×640, 390×844, 가로 화면에서 슬롯 간격·스프라이트 크기·실제 유닛 선택을 기록한다. 서버의 좌표와 피해 판정이 표시 변화로 바뀌지 않는지 확인한다.
- 실제 HTTP로 solo 추가 입장/스토리 없음, coop 재접속/파견/공통 보상과 엔진 비용을 확인한다. 기존 튜토리얼·판매·회전·조립 위치 검사를 재사용한다.
- 전체 빌드/Node 검사와 가능한 C# 계약 검증을 수행한다. Unity Editor/iPhone/실제 사람 검증 여부를 구분한다. 봇 실험은 사람 승률로 해석하지 않는다.

## 반영 결과와 전후 측정

콘텐츠 버전은 **0.14.0-command-deck**다. 서버 모드와 입장 거절, 웹·Unity 모드 전달/재접속, 조립 진행, 등방 전장 투영, 시설 군집 표시를 구현했다. 데이터의 버전 외 값은49a211d와 동일하다. 준비→군집→장갑→보스 공세는 기존 encounterPreview를 사용하며 별도 적 계열/성장 규칙은 추가하지 않았다.

전장 위 조립 표시와 적 대형만 추가하고 기존 PNG·공격 반동·효과음을 사용한다. 적의 표시 대형은 같은 위치의 군집을 구별하기 위한 것으로 공격/사망 효과에도 같은 좌표 변환을 적용한다. 실제 이동 속도나 시설 도착 시각을 바꾸지 않는다. 조립 재료 2/3 안내는 선택만, 실제3/3은 선택 기준 위치에서 확인 조립한다.

## 입력 가림 보정

단순히44px 버튼과30% 설명창을 확보하는 것만으로는 충분하지 않았다. 최초 전수 검사에서 로봇 터치264회는 통과했지만 선택 후128회는 고정 설명창이 선택 중심을 가렸다. 따라서 기존 위치 고정 테스트를 전장/로봇 좌표와 창 크기 유지·선택 중심 비가림·화면 경계·폴링 안정성 검증으로 바꿨다. 정보창은 선택·회전·위험 경고 표시 변경 시 후보 위치를 정하고, 틱 갱신 때마다 움직이지 않는다. 주요 조작/위험 HUD를 유지하면서 로봇 본체와 보조 정보의 가림도 최소화한다. 작은 화면의 본체 전체 가림 여부는 중심 가시성과 별도로 계측한다.

튜토리얼의 직접 로봇 선택 단계 안내는 작은 가로형 카드로 줄였고,3·4구역 관제 메시지는 경로 바깥에2.5초만 표시한다. 상시 위험 경고/보스 정보는 유지한다.

## 검증과 남은 범위

빌드·Node293개, C# 데이터/모델 계약20개, 모드 브라우저18흐름을 통과했다. [독립 QA](../reviews/2026-09-29-ord-adaptation-qa.md)의 추가 HTTP7경계 검사에서도 새 결함이 재현되지 않았다. 최종 입력 회귀 결과는 [최신 인계](../LATEST_HANDOFF.md)에 기록한다.

[89경기 감사](../playtests/2026-09-29-ord-adaptation.md)에서는 개인전과 파견 없는1인협동29쌍의 개인 결과가 일치했다. 첫 두 구역의 난도를 유지했으며 후반 보스 시간 초과는 기존 문제로 기록했다. 이 결과는 사람 승률이나 재미 향상을 입증하지 않는다. 공개 매칭·협동 대기방·8인 확대·Unity Editor/iPhone 실행은 남아 있다.

입력 전수검사:360×640/390×844/844×390,1·3·5구역,기본/S강제배치의18조건·264터치에서 선택중심264/264·본체전체228/264가 설명창 밖에 있었다. 가장자리 일부가 겹친36회는 본체 전체 비가림과 구분한다. 실제 판정·44px터치·30%창·주요경고를 우선한 결과이며 좁은 화면의 여백은 계속 제약이다. 엔진/5맵은360×640/390×844/667×375의18검사를 통과했다.

본체 일부 겹침36회는360×640에서16회,844×390에서20회였고390×844는0회였다. 본체 사각형 기준 최대31.8%(360×640,3구역 기본 로봇), 가로 화면 최대7.4%다. 원형 선택 표시/본체 중심 가시성과 본체 전체 비가림은 다른 지표다.

최종 회귀: 설명창/조립/회전5규격, 튜토리얼12개, 원정 흐름19개 통과. 회전 직후1프레임에 과거 좌표가 남는 문제는 CSS 크기 변수와 위치 clamp로 화면 경계를 즉시 지키게 보정했다. 360×640/3구역 두 등급28터치도 추가 확인했다. 과밀·보스 경고 등장/해제 시1회 재배치하고 카운트다운 중 위치가 안정적인지 실제 서버 상태로 확인했다.
