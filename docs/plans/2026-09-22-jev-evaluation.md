# JEV Ultrafast 도입 검토

2026-09-22. 상태: **공개 문서·소스 검토만 완료. 미설치·미실행, API 호출이나 게임 코드 변경 없음.**

사용자가 지정한 [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast)를 현재 `0.7.0-expedition-siege`와 비교했다. [앞선 20개 페르소나 검토](2026-09-22-art-direction-review-design.md)의 전문가 13명·소비자 7명 관점을 유지했다. 실제 인터뷰나 JEV 사용 결과가 아니다.

## 판단

**홈·메뉴·설명의 목표 기반 탐색을 보조하는 작은 실험을 추천한다.** 현재 Playwright 회귀 검사, 서버 시뮬레이션, 실제 폰에서의 시각·청각 검토는 유지한다. JEV를 게임 안의 기능이나 필수 실행 의존성으로 넣을 이유는 현재 없다.

JEV는 자연어 목표를 받아 관찰한 HTML 요소 중 클릭·입력·선택 등의 행동을 고르는 브라우저 에이전트다. 기본 루프는 구조화된 페이지 정보를 사용한다. 즉, “첫 원정을 시작하라”라는 목표를 주고 메뉴를 찾아가는 경로를 살펴보는 데 도입 가치가 있다. [공식 소개](https://github.com/browser-use/jev-ultrafast#the-action-space).

## 확인한 기능과 우리 프로젝트의 경계

| 확인한 소스 사실 | 우리 프로젝트에서의 의미 |
|---|---|
| `model.py`의 판단 입력은 URL·제목·텍스트·요소와 최근 행동 | 글꼴 형태, 색감, 캐릭터 매력, 애니메이션 무게, 소리를 직접 평가하지 못한다. 스크린샷 기록 옵션을 켜도 현재 판단 모델이 이미지를 보는 구조로 바뀌지 않는다. |
| `snapshot.js`는 일반 HTML/ARIA 조작 요소를 수집하고 문서 단위 스크롤을 제공 | 홈·행성 버튼은 후보. Canvas 안 로봇 선택과 연구·조립 패널의 내부 스크롤은 지원 한계에 걸린다. |
| `browser.py`는 1120×780, `mobile=False`로 시작하고 마우스 이벤트로 클릭 | 그대로 실행한 결과를 390×844 터치 UI 또는 실제 iPhone 시험이라고 보고할 수 없다. |
| `agent.py`는 모델의 `DONE` 선택을 완료 상태로 기록 | 합격은 별도 검증기가 DOM·서버 상태를 보고 판단해야 한다. 완료 선언만으로 성공으로 집계하지 않는다. |

근거: [모델 입력](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/model.py), [요소 수집](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/snapshot.js), [브라우저 입력](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/browser.py), [완료 처리](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/agent.py).

우리 앱에는 Canvas 외에 기존 로봇 목록의 DOM 카드가 있다. `app.js`의 `.unit-card` → `selectUnit()` → 유닛 팝업 경로는 탐색 후보이므로 “모든 조립 UI가 불가능하다”고 해석하지 않는다. 다만 목록 밖 카드·긴 조립 경로·연구 항목은 가로 또는 내부 스크롤이 필요하다. JEV를 통과시키려고 별도 우회 UI를 만들거나 실제 화면을 바꾸지 않는다.

| 20 양산형 경계 이용자 | 연습과 보상 있는 원정의 선택 구분 | 게임 표현의 신뢰감·거부감 |

페르소나의 과제 중 “조건을 찾기”는 해당 설명이 표시된 위치에 도달시키고 검증기가 내용을 확인한다는 뜻이다. 기본 JEV가 자동으로 사용성 비평·문구 개선안·소비자 감상 보고서를 작성한다는 뜻은 아니다. 행동 기록의 해석은 별도 리뷰 작업이다.

## 토론과 선택

- **UX 라이터·프로듀서:** 지정된 선택자를 클릭하는 검사에 더해, 문구와 목표로 경로를 찾게 하면 예상 못 한 메뉴 선택을 발견할 수 있다.
- **모바일 기술 담당:** 기본 환경이 데스크톱이고 지원하지 않는 UI가 많다. 실패를 전부 게임 결함으로 보고하면 오히려 수정 방향이 틀어진다.
- **아트·캐릭터·애니메이션 담당:** 이번 “AI 티” 논의의 시각·감성 판단을 맡길 수 없다. 기록된 화면은 사람이 검토하는 자료로 쓸 수 있다.
- **소비자 관점:** ‘설정 찾기’의 성공은 유용하지만 ‘글씨가 편하다’, ‘캐릭터가 마음에 든다’와 같은 판단으로 대체하면 안 된다.

정리한 제안은 **명확히 지원되는 과제 3개부터 시험하고, 추가 가치가 확인될 때 2개를 넓히는 방식**이다. AI를 20회 실행해도 실제 소비자 20명의 반응이 되지 않으며, 에이전트 소요 시간을 사람의 사용성 시간으로 비교하지 않는다.

## 실행한다면 할 작은 실험

### 1차: 3개 과제 × 3회, 총 9회

| 자연어 목표 | 별도 검증기가 확인할 결과 |
|---|---|
| 설정에서 움직임을 줄이고 효과음을 끈 뒤 홈으로 돌아간다. | 두 설정 값과 홈 복귀. 소리·동작의 체감 품질은 별도 확인 |
| 3배속 연습을 선택해 보상 없음을 확인한 뒤, 1배속 원정으로 되돌리고 출발하지 않은 채 홈으로 돌아간다. | 선택값·보상 안내 일치, 최종 1배속, 의도치 않은 방 생성 없음 |
| 첫 일반 원정을 시작하고 로봇을 정확히 한 번 뽑는다. | 일반 원정 상태, 성공 소환 1회, 서버의 로봇 수·고철 변화 |

이 횟수는 연결과 실패 유형을 알아보기 위한 예비 실험이며 신뢰도나 성공률을 일반화하기에 충분한 표본이 아니다. 과제는 시작 상태를 매번 초기화한 테스트 계정에서 수행한다. 실시간 경기 분석이 목적이 아니므로 기존 서버의 제어된 시계·상태 구성도 재사용할 수 있다.

### 2차 후보: 제한을 확인한 뒤 추가

- 첫 화면에서 접근 가능한 설계도 → 조립 경로 열기 → 닫기. 정확한 항목과 경로가 보이는지 확인한다. 긴 내부 스크롤은 첫 실험에 넣지 않는다.
- 준비된 테스트 방 코드로 참가하기. 서버의 방·플레이어 상태로 판정한다. 네 개의 같은 프로필 탭을 독립된 네 명으로 간주하지 않는다.

### 기록·채택 기준

- 고정된 JEV 버전·모델 설정·과제·초기 상태를 기록한다. 기존 Playwright로 같은 기능 결과를 확인한다.
- 기록: 실제 완료, 오클릭, 왕복, 재시도, 모델 호출 수, 확인 가능한 전체 비용과 누락 항목, 유지에 든 작업량.
- 실패는 **게임 기능 결함 / 문구·탐색 문제 후보 / JEV 지원 한계 / 에이전트 판단 오류·서비스 오류**로 나눠 재현한다. 사람이 재현·판독한 뒤 개선 여부를 정한다.
- 새로운 문제를 찾거나 문구·레이아웃 변경 뒤 탐색 검토 작업을 실제로 줄일 때 보조 도구로 채택한다. 기존 검사에 비해 새 가치가 없거나 내부 스크롤 대응에 별도 개발이 많이 필요하면 보류한다.
- 출시 합격 여부는 JEV의 `DONE`과 모델 확률로 결정하지 않는다. 최종 미술·동작·소리 검토와 실제 이용자 비교는 앞선 개선 계획을 따른다.

## 환경·비용과 역할 분담

JEV에는 Python 3.12 이상과 고정 의존성 `browser-harness==0.1.13` 등이 필요하다. 우리 Node/Playwright 개발 도구에 별도 환경이 추가된다. 현재 Windows에서 연결을 확인하지 않았으며, 최신 Harness의 기능 설명을 이 고정 버전의 지원 보장으로 해석하지 않는다. [프로젝트 의존성](https://github.com/browser-use/jev-ultrafast/blob/main/pyproject.toml).

행동 선택에는 TypeSafe API 키, 텍스트 입력에는 별도 텍스트 모델 키가 필요하다. 모델로 페이지 정보가 전달되는 구조이므로 실험에는 테스트 데이터와 별도 브라우저 프로필을 쓴다. 실제 프로필·게임 저장 상태와 분리하고 키를 게임 클라이언트에 넣지 않는다. [모델 호출 코드](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/model.py).

공개 성능 자료의 7초대 사례는 항공편 검색의 제한된 조건이다. 게임 탐색에서 같은 속도를 보장하지 않는다. 예시 `$0.00006272`도 텍스트 생성 2회의 비용으로, TypeSafe와 브라우저를 포함한 전체 작업 비용이 아니다. 도입 비용은 우리 실험의 모든 호출과 설정·유지 작업을 확인한 뒤 판단한다. [성능·비용의 측정 범위](https://github.com/browser-use/jev-ultrafast/blob/main/docs/performance.md).

| 확인할 일 | 우선 도구/방법 |
|---|---|
| 메뉴·문구를 따라 목표에 도달하는 다양한 경로 | JEV의 제한적 탐색 실험 + 기록 리뷰 |
| 뽑기·조립·판매·강화·해금의 정확한 결과 | 기존 Playwright + 서버 상태 검증 |
| 확률·조합 가능성·난이도·장기전 결과 | 기존 시드 기반 서버 시뮬레이션과 실제 플레이 |
| 4인 이상 동기화·재접속·개인 구역 분리 | 독립 클라이언트를 사용하는 기존 네트워크 검사 |
| 폰트·아트·애니메이션·효과음의 매력과 거부감 | 화면/영상/음향 리뷰와 실제 휴대폰 이용자 검토 |

다음 단계는 위 1차 실험의 필요성을 정한 뒤 전용 환경·API 설정·실행 한도를 준비하는 것이다. 이번 요청에서는 설치나 유료 실행까지 진행하지 않았다.
