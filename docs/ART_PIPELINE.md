# 아트·애니메이션 제작 기준

조사일: 2026-09-19. 이 문서는 제작팀 기본안이며, 완성된 아트나 구입한 자산 목록이 아니다. 외부 자산 다운로드·구매·설치는 하지 않았다.

## 제작 방향

초기 전투는 코드로 그린 독자적인 도형 캐릭터에 이동, 공격 반동, 피격 반짝임, 소환 파동을 붙여 검증한다. 정식 캐릭터는 **독자적인 SD 삼국지 일러스트 + Unity 2D Animation 파츠 리깅**을 기본으로 한다. 전투 가독성과 제작량을 검증한 뒤 전체 27종으로 늘린다.

애니메이션은 완성된 움직임이 포함된 스프라이트 팩을 구할 수도 있고, 직접 만든 그림을 파츠별로 움직일 수도 있다. 서로 다른 상점의 장수 그림을 섞으면 비율·시점·명암이 달라지므로, 핵심 장수는 통일된 디자인으로 직접 제작하거나 같은 규격으로 발주한다. 구매나 외주 계약은 아직 없다.

Unity 공식 문서는 프레임 교체, 컷아웃, 뼈대 변형을 구분한다. 이 프로젝트는 일반 몸동작을 파츠 리깅으로 만들고, 검기·폭발·과장된 타격 포즈는 프레임 그림을 보조로 쓰는 방식이다. [Unity 2D 제작 흐름](https://docs.unity3d.com/6000.1/Documentation/Manual/2d-game-creation-wokflow.html)

Unity 6.3에는 2D Animation 13.x 계열이 대응하며, 파츠 그림을 PSB 레이어로 가져오는 경로도 제공한다. 실제 프로젝트의 지원 패치와 패키지를 확인하고 버전을 고정한다. 설치 완료를 뜻하지 않는다. [2D Animation 공식 문서](https://docs.unity3d.com/Packages/com.unity.2d.animation@13.0/manual/index.html)

### 첫 동작 세트

리깅은 아래 길이에 키를 배치하고, 프레임 방식이면 아래 프레임 수를 기준으로 납품한다. 12fps는 그림 교체 속도이며 앱 화면 갱신 속도가 아니다.

| 상태 | 프레임 방식 기준 | 리깅 길이 | 반복·시점 |
| --- | --- | --- | --- |
| idle | 8장 / 12fps | 약 0.67초 | 반복, 작은 호흡 |
| walk | 8장 / 12fps | 약 0.67초 | 반복, 적 이동과 파견 연출용 |
| attack | 6장 / 12fps | 0.50초 | 1회, 준비 0~0.17초·타격 포즈 약 0.25초·복귀 |
| hit | 2장 / 12fps | 약 0.17초 | 1회, 이동 루트는 유지 |
| death | 6장 / 12fps | 0.50초 | 적에게 우선 적용, 완료 후 표시 제거 |
| cast | 8장 / 12fps | 약 0.67초 | 지략·지원 유닛만 추가 |
| summon FX | 8장 / 12fps | 약 0.67초 | 소환 결과가 확정된 뒤 1회 |

공격·피격·사망은 서버 결과를 시각화한다. 애니메이션 이벤트가 피해량, 대상 생존, 소환 결과를 결정하지 않는다. 첫 프로토타입에 전투 이벤트가 아직 없으면 스냅샷의 위치·체력·유닛 추가/삭제 변화로 가능한 연출만 한다. 정확한 타격 동기화는 서버 tick과 이벤트 ID가 연결된 뒤 검증한다. 재접속 시 과거 소환 연출을 재생하지 않는다.

### 임시 연출 구현 기준

- 이동: 서버 위치를 표시용 위치로 보간한다. 걷기 흔들림은 자식 그림에만 적용한다.
- 공격: 그림을 대상 방향으로 0.08초 밀고 0.12초에 복귀한다. 투사체는 시각 효과이며 자체 충돌 피해를 계산하지 않는다.
- 피격: 0.10초 밝게 표시하고 약하게 축소·복원한다. 연속 피격 시 무한 중첩하지 않는다.
- 소환: 그림 크기 0 → 1.12 → 1, 약 0.30초. 원형 파동은 약 0.45초 후 제거한다.
- 대박: 해당 장수·등급·플레이어 이름을 짧게 표시한다. 일반 소환과 구분하되 전체 전장 조작을 막지 않는다.
- 연출 축소 설정에서는 흔들림·섬광을 줄이고 결과 텍스트와 상태 정보는 유지한다.

## Unity 반입·검수

1. 독자 PNG를 Sprite (2D and UI), 일반 SD는 Bilinear, Mip Maps 끔, PPU 128로 시작한다. 256px 캔버스는 2 Unity unit이며 실제 배치 크기는 화면에서 맞춘다. 도트 후보만 별도 Point 설정을 쓴다.
2. 프레임 시트는 같은 크기의 셀로 Slice한다. 256px 셀의 8프레임 가로 시트는 2048×256이다. 512px 보스 8프레임은 4×2로 배치해 2048×1024로 만든다. 임의 Trim으로 발이 흔들리지 않게 한다.
3. 캐릭터·전장·UI 아틀라스를 용도별로 나누고 2048 크기부터 측정한다. iOS 압축은 가독성·알파 경계를 실기기에서 확인한 후 정한다.
4. 전투 화면의 최종 표시 크기에서 유닛·등급·파견 상태를 구분한다. 파츠 틈, 발 미끄러짐, 무기 잘림, 공격 종료 후 자세 복귀를 확인한다.
5. 최대 전투 수량에서 메모리·프레임·발열을 측정한다. 리깅이 비싸면 적이나 원거리 전장은 프레임 방식 또는 간소화 표시를 비교한다. 미측정 성능을 보장하지 않는다.

## 제작 순서와 산출물

| 단계 | 산출물 | 완료 판단 |
| --- | --- | --- |
| A — 규칙 검증 | 독자 도형 캐릭터와 이동·공격·피격·소환 효과 | 공격과 결과를 알아볼 수 있고 연출이 판정을 바꾸지 않음 |
| B — 대표 1세트 | 보병 1, 궁병 1, 책사 1, 적 1, 보스 1. 원본·리깅/클립·아이콘·효과 | 한 화면에서 크기·시점·움직임 통일, 아이폰 표시 검증 |
| C — 콘텐츠 확대 | 기본·정예·영웅·전설 총 27종 목표, 전장별 적·배경 | 콘텐츠 ID와 그림 연결, 조합 전후 식별, 누락 동작 없음 |
| D — 출시 정리 | 임시 그림 교체, 출처 대장, 크레딧, 성능 조정 | 외부 자산 사용 조건과 납품 기록 확인, 실제 기기 검사 통과 |

대표 세트의 실제 작업 시간을 측정한 뒤 전체 일정·외주 비용을 산정한다. 현재는 담당 아티스트와 실측 제작 속도가 없으므로 납기·견적을 확정하지 않는다. 일반 유닛끼리는 뼈대·기본 동작을 공유하되 장수별 얼굴·무기·대표 동작으로 구분한다.

현대 게임·만화의 캐릭터, 맵, 음성, 모션 파일을 추출하지 않는다. 삼국지 인물을 소재로 사용하더라도 구체적인 디자인·대사·연출은 독자 제작한다. 실제 반입 파일은 [자산 대장](../assets/manifest.json)에 기록한다.
