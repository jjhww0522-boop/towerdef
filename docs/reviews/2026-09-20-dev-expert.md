# 개발 전문가 관점 검토 — 2026-09-20

이 문서는 실제 외부 전문가 자격을 주장하지 않는 개발 전문가 역할의 모의 검토다. 게임 설계자 및 숙련 플레이어 관점과 메시지로 제안·반론·수정안을 교환했다.

## 최초 제안

1. 선택한 유닛 중심으로 현재 → 다음 진화, 필요한 재료를 표시한다. 실행 가능 여부는 기존 서버 합성 조건을 따른다.
2. 전장과 초상화가 동일한 원본 벡터 캐릭터를 사용하게 한다. 큰 머리, 두꺼운 외곽선, 진영색, 무기로 유닛을 구별하고 기존 외부 PNG 로딩 의존을 없앤다.
3. 실제 서버 `lastAttackTick`에 연결한 팔·무기 공격 자세와 네 단계의 적 보행을 구현한다. 이펙트 120개 제한, 저모션 설정, 모바일 좌표계를 보존한다.

## 반론과 수정

- 게임 설계자는 색·무기가 아직 없는 탱킹·사거리 능력을 암시할 수 있다고 지적했다. 수용: 무기는 기존 병종 태그의 시각적 구별에만 사용하고 실제 존재하지 않는 전투 역할 설명을 추가하지 않는다.
- 숙련 플레이어는 보행 디테일보다 선택·파견 구별이 우선이며 작은 화면에서 두 단계로 줄일 여지도 있다고 제안했다. 선택 대비 우선에는 동의했다. 다만 네 단계는 같은 SVG의 다리 각도 변화로 추가 화면 공간이 필요하지 않으므로, 네 단계를 유지하고 진한색/밝은색 이중 선택링과 저모션 고정을 적용하자고 반론했다. 숙련 플레이어가 수정안을 수용했다. 저비용 구조라는 판단은 실제 기기의 성능 보장을 의미하지 않는다.
- 결과 태그만 보여 주면 어떤 개체가 소비되는지 놓칠 수 있다고 게임 설계자에게 반론했다. 선택한 정확한 ID가 재료에 포함되고, 합성 후 새 ID 결과로 포커스를 옮기는 동작을 UI 구현에서 우선해야 한다.
- 파견의 평균 DPS를 안전 보장으로 사용하지 않는 데 동의했다. 이름·남는 인원·확정 복귀 조건을 우선하고, 설명과 실제 규칙을 일치시킨다.

## 구현 범위

- `playtest/casual-art.js`: 직접 작성한 원본 SVG. `unitSpriteUrl(definition)`으로 초상화와 전장에 같은 디자인을 공급한다. 대기·공격 준비·공격 자세에서 팔과 무기 각도가 바뀌며, 적 보행은 다리 위치가 바뀐다.
- `playtest/battlefield.js`: 밝은 잔디와 단순한 석조 경로, 원본 벡터 유닛, 이중 선택링을 적용했다. 데스크톱 1000×440 / 모바일 600×700, 서버 공격 시점, 소환·파견·피격·사망 표시를 유지했다.
- 서버 전투 규칙과 밸런스는 변경하지 않았다. 진화 UI는 상위 작업자가 담당한다.

## 검증

`node --test tests/battlefield.test.mjs`: 9개 통과. 최초 관전 시 과거 공격 미재생, 공격 중복 방지, 체력·사망 표시와 서버 데이터 불변, 120개 효과 제한, 저모션, 경로 순환, 모바일 배치, 실제 보행·공격 포즈 선택, 회전 시 좌표 보정을 확인했다.

`node --check playtest/battlefield.js` 및 `node --check playtest/casual-art.js` 통과. 실제 브라우저의 그래픽·모바일 레이아웃 최종 검증은 상위 작업의 브라우저 검증 결과와 함께 확인한다.
