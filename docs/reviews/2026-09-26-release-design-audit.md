검토 기준: `a8ad01e`, 콘텐츠 `0.10.1-training-combat`, `docs/LATEST_HANDOFF.md`의 최신 항목, `shared/content.json`, `server/core/index.ts`. 이 문서는 설계 페르소나의 코드·문서 검토다. 실제 이용자 조사·휴대폰 검증·출시 승인을 뜻하지 않는다. 참고작의 출처와 차용 범위는 [참고 대장](../reference/2026-09-26-reference-ledger.md)에 남겼다.

## 제품을 관통하는 방향

**다가올 위협을 읽고, 폐품 로봇을 조립하고, 방어가 달라진 결과를 이해하는 원정.** 새 성장 체계를 겹쳐 넣기보다 이미 있는 속성·사거리·조립·시설 방어를 하나의 판단 흐름으로 연결한다.

대안 세 가지를 비교했다. 외형만 교체하면 전투가 반복되는 이유가 남고, 카드 선택·영구 장비·이동 배치를 한꺼번에 추가하면 튜토리얼과 경제를 다시 설계해야 한다. 권장안은 적 역할과 공세 예고, 제한된 전술 선택, 실제 판정에 맞는 전투 표현을 함께 개선하는 것이다. 새로운 행성·결제·메타 성장 체계는 이 변화의 효과를 검증한 후 판단한다.

## 권장하는 개편 단위

### A. 공세 예고와 역할이 다른 적

서버가 결정한 공세 역할과 다음 전환 시점을 표시하고 실제 생성에 동일한 정의를 사용한다. 적 역할은 기본형, 빠른 침투형, 무거운 공성형, 낮은 체력의 군집형처럼 소수로 시작한다. 새 공세를 위해 소환 난수를 더 소비하지 않는다. 등장 수·체력·이동·시설 피해의 총압박을 함께 보고, 적 종류가 늘었다고 기존 생성량에 무조건 더하지 않는다.

빠른 적에는 냉동으로 노출 시간을 늘리는 선택, 군집에는 바람·전격의 다중 적중, 무거운 적에는 집중 화력이라는 기존 역할을 연결한다. 팀 조율 후 장갑 감소·화염 관통 예외는 이번 범위에서 제외했다. 특정 속성이 없다는 이유만으로 피해가 0이 되는 완전 면역도 넣지 않는다.

검증: 예고와 실제 생성 일치, 신규 시퀀스의 난수 불소비, 다중 입구의 실제 거리, 감속과 시설 도달, 훈련 기존 스크립트 보존. 자동 정책은 1~5단계 및 1인/4인을 모두 실행하고 같은 계열 시드에서 변화를 비교한다.

### B. 전술 지원은 반복 클릭보다 위기 판단에 쓰인다

코어 담당 제안은 공유 대기시간 아래 짧은 공격 증폭과 적 정지를 고르는 방식이다. 방어가 이미 자동인 게임에서 즉시 개입할 수 있는 창구가 된다는 장점이 있다. 초기 25초안에 조작 부담을 지적했고 팀은 40초 공유 대기시간으로 조율했다. 그래도 매번 눌러야 기존 난도를 따라가는 필수 숙제가 되면 실패다.

버튼 두 개의 실행 가능 상태·공유 대기시간·유효 시간을 서버 상태에서 보여 준다. 행동 거절·재전송·재접속·개인 패배 후 사용의 비용과 효과가 정확해야 한다. 파견 병력에 적용되는지, EMP가 이동만 멈추는지 공성 공격도 멈추는지, 보스에 줄어든 시간이 적용되는지 명세를 하나로 고정한다. 지원을 설명하기 위해 기존 훈련 전체를 늘리기보다 일반 전투에서 비차단 안내를 검토한다.

검증: 지원 무사용/증폭을 매번 사용/EMP를 시설 위험에 사용 정책을 비교한다. 신종 적 추가와 지원 추가의 효과를 따로 볼 수 있게 한다. 무사용 자동 전략의 실패 증가를 지원의 재미 증거로 해석하지 않는다.

### C. 공격·상태·위협의 정보 우선순위

시설 위험·보스 시간 → 선택 로봇·조립 위치 → 실제 적중·군중제어 → 장식 잔상 순서로 읽히게 한다. 현재 `lastAttackHits`를 활용해 1차와 추가 타격을 연결하고, 이미 쓰러진 대상도 기록된 경로 위치에서 짧게 맞은 흔적을 보여 준다. 명중 연출을 위해 서버 체력 변화나 경로 이동을 늦추지 않는다.

적 역할은 실루엣과 보조 표식으로 구분하고 색에만 의존하지 않는다. 냉동과 정지는 다른 상태로 그린다. 전술 지원의 지속 효과와 한 번 발생하는 폭발을 구분한다. 시설 피격음은 개별 로봇 타격음보다 우선하며 밀집 전투에서도 노드·이펙트 상한을 둔다. 동작 줄이기는 상태 정보까지 숨기지 않는다.

검증: 실제 적중 없는 유령 타격 없음, 보스/시설위험과 팝업 겹침 없음, 360×640·390×844·667×375에서 전장 크기와 44px 조작 유지, 고밀도 전투에서 상태 식별. 자동 캡처 통과는 실제 아이폰 성능이나 사람이 알아봤다는 증거가 아니다.

### D. 결과가 다음 판의 판단으로 이어진다

현 패배 원인을 유지하면서 시설에 도달한 위협과 이번 판의 주된 대응을 짧게 보여 주는 방향이 좋다. 아직 기록하지 않은 기여 수치나 실제 원인이 아닌 ‘최적 조합’을 추측해 출력하지 않는다. 이번 구역에서 얻는 조합 해금은 기존 성장 체계에 연결하고 새 능력 이름으로 혼동시키지 않는다.

런 길이·보상·연구 가격·뽑기 확률을 이번에 함께 바꾸면 개선 원인을 알기 어렵다. 기본 시간표는 유지하고 다음 공세 정보와 보스 접근으로 구간의 성격을 만든다. 채굴 종료는 보스가 없는 목표라는 점을 끝까지 유지한다.

## 팀 토론과 수정

- 코어 담당은 적 역할+전술 지원을 제안했다. 설계 측은 오래된 적 우선 타격을 시설 위협 우선으로 바꾸는 것도 검토했지만, 적 종류·지원과 동시에 바꾸면 원인 분리가 어렵다는 코어 반론을 수용해 이번 우선 범위에서 내렸다.
- 설계 측은 장갑/화염 관통이 새 예외 규칙이므로 단순 고체력 공성형보다 설명 비용이 높다고 반박했다. 채택 시 피해 감소·관통의 명시, 완전 면역 배제, 기존 짧은 화염 사거리까지 포함한 검증을 요구했다.
- 설계 측은 짧은 공유 대기시간이 긴 구역에서 반복 조작 부담을 만들 수 있다고 지적했다. 무사용·상시사용·위기대응 정책 비교를 권고했다. 수치는 실제 비교를 거쳐 코어 담당과 root가 확정한다.
- 표현 담당은 실제 적 유형에 따른 실루엣, 확인된 적중 기반 짧은 반동, 실제 정지·증폭 상태, 경고 우선 오디오를 제안했다. 서버 시간은 멈추지 않고 몸체 표현만 짧게 유지하며, 구현되지 않은 보스 스킬의 예고원을 넣지 않는 계약에 동의했다.

## 출시 품질 판단의 남은 조건

새 전투의 코드·브라우저 검증 외에 실제 휴대폰의 장시간 성능·열·음향과 신규 플레이어의 첫 공세 이해도는 별도 증거가 필요하다. 신규 적 이름을 맞히는 것보다 ‘왜 내 로봇이 공격하지 않았는지 / 왜 시설이 손상됐는지 / 다음 판 무엇을 바꿀지’를 설명할 수 있는지를 본다. 유료 스토어 연결·네이티브 출시·실제 계정 환경 검증을 이 전투 업데이트의 자동 테스트로 대체하지 않는다.

## 원정 이야기 원본

추가로 `playtest/mission-content.js`에 다섯 구역의 짧은 독자 대사를 작성했다. 착륙 지대 확보→채굴 완료→엔진 보호→양갈래 협곡→탈출항의 흐름이며 지구로 가져갈 자원과 귀환이라는 기존 설정을 따른다. 2번은 보스 없이 채굴 완료, 다른 구역은 기존 시간 뒤 보스라는 실제 목표를 유지한다. 자원 운반·엔진 수리·별도 대사 보상 같은 미구현 조작을 요구하지 않는다.

각 구역은 `chapter`, `title`, `briefing`, `speaker`, `opening`, `midpoint`, `warning`, `victory`, `defeat`, `lesson`의 plain string이다. 중간·경고 대사는 비차단 통신과 작전 기록에 사용하고, 실제 전환 시점·승패 상태에 맞추는 책임은 소비 UI에 있다. 대사 때문에 전투가 자동으로 멈추거나 튜토리얼이 추가되지 않는다.

이 문서 작성자는 연구·설계 문서와 위 대사 모듈을 작성했다. 적용된 최종 전투 수치와 변경 파일, 테스트 결과는 구현 담당자의 최신 인계를 기준으로 한다.
