- 날짜: 2026-09-26
- 대상: `feat/reignition-overhaul`, 기준 `a8ad01e` 이후의 작업 트리 및 신규 모듈. 콘텐츠 `0.11.0-reignition`.
- 범위: 서버 공세·전술·통계 계약, HTTP/Nakama 전달, 저장 진행 보존, 브라우저 효과와 신규 조작 영역. 검토자는 제품 코드를 수정하지 않았으며 아래 CSS 수정은 통합 담당자가 적용했다.

## 발견 사항 — P2 1건, 수정 및 재검증 완료

### P2-01 · 전술 상태 문구가 채굴장의 마지막 로봇 선택을 막음 — 해결

- 위치: `playtest/operation-ui.css:21`의 `.tactical-controls`, `:22`의 `#tactical-status`.
- 조건: 360×640, 2번 채굴장, 0부터 세는 슬롯 11의 기본/개조 로봇. 신규 지원 문구가 해당 로봇 중앙을 덮고 포인터 이벤트를 가져갔다.
- 재현: 영구 파일을 쓰지 않는 메모리 프로필과 수동 서버 시계를 사용해 채굴장 12칸에 로봇을 놓았다. 렌즈아이의 중앙 `(224.64, 471.984)`에서 `document.elementFromPoint`가 Canvas 대신 `#tactical-status`를 반환했다. 실제 마우스 입력 `(224, 472)` 후 `#unit-dialog.open`은 `false`였다.
- 영향: 로봇을 직접 눌러 조립/관리하는 기본 조작이 해당 자리에서 실패했다. 목록을 통한 접근은 가능하므로 전체 진행 차단은 아니었다.
- 수정: 컨테이너는 `pointer-events:none`, 실제 전술 버튼은 `pointer-events:auto`로 지정했다(`playtest/operation-ui.css:23`, `:25`).
- 재검증: 시험용 인라인 스타일을 모두 제거하고 수정된 CSS 파일을 다시 받아 같은 좌표를 실제로 클릭했다. Canvas에 입력이 전달되고 렌즈아이 선택 창이 열렸다. 과부하/EMP 버튼 중앙은 모두 실제 버튼으로 히트되어 계속 조작 가능했다.

## 직접 확인한 근거

1. 다음 검사 **38/38 통과**: `tactics-encounters`, `operation-model`, `progression`, `engine-api`, `nakama`, `nakama-concurrency`, `http` 테스트. 통합 담당자의 전체 테스트 결과를 독립 실행한 것으로 계산하지 않았다.
2. 별도의 HTTP 실행 탐침: 실제 `/session` → `/action`에서 소환과 과부하 성공, 같은 요청 재전송은 사용 횟수 1회, 같은 seq의 EMP 변경은 `SEQUENCE_REUSED`. 본문에 다른 `playerId`를 넣어도 인증된 참가자에게만 적용되었다.
3. 별도의 빌드된 Nakama VM 실행 탐침: 4인 참가 → 소환 → 과부하 → 재전송에서 사용 횟수 1회, 동료 사용 횟수 0회. 다른 sessionId의 송신 요청은 처리되지 않았다. `server/nakama.ts:84`와 `tools/dev-server.mjs:203`은 검증된 송신자 ID를 코어에 전달한다.
4. 전술 경계: 400틱 공유 쿨다운, 본진에만 60틱 1.5배 피해, 사용 당시 적만 30틱/보스 10틱 이동·공성 정지. 실패·재전송은 효과를 연장하지 않는다. 공개 상태의 남은 시간이 0인 시점은 해당 틱의 판정이 끝난 상태이며 다음 틱에 정상 행동한다.
5. 결과·저장: `server/core/index.ts:184`는 지원 횟수까지 복사한다. 은퇴한 플레이어는 후속 전투 누적에서 제외되며, 보고서 웨이브·통신 시점도 자신의 확정 결과를 사용한다. 기존 엔진 입장·연구·해금·중복 보상·레거시 저장 테스트가 통과했다. 실제 사용자 저장 파일은 읽거나 변경하지 않았다.
6. 브라우저 위치 검사: 실제 `agent-browser`와 Chrome에서 360×640, 390×844, 667×375, 1440×900 Canvas의 크기를 측정하고 기존 `Battlefield.position`/`unitHeight`로 5개 맵·4개 희귀도의 로봇 중앙을 투영했다. 수정 후 새 UI가 막는 중앙은 0개였다. 이는 5개 맵 전체의 실제 장기 전투를 실행한 검사가 아니라 배치 좌표와 DOM 히트 영역의 대조다. 실제 맵 전환과 클릭 재현은 5번/2번을 열어 수행했고, 위 회귀의 전후 클릭은 2번에서 확인했다.

## 검토 한계

코드와 통제된 브라우저/서버 환경에서 확인한 판정이다. 실제 모바일 기기의 장시간 성능·음향, 신규 이용자의 이해도, 실제 Nakama 서비스 연결을 새로 검증한 것으로 확대 해석하지 않는다. 기존 전체 브라우저·밸런스 실험의 실행 범위는 통합 담당자의 플레이테스트 기록을 따른다.
