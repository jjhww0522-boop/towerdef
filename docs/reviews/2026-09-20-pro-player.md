# 숙련 플레이어 관점 내부 검토 — 2026-09-20

역할: 프로 게이머를 가정한 숙련 플레이어 **페르소나**. 실제 프로 선수의 경력이나 실제 이용자 인터뷰·관찰 자료가 아니다. 제작 책임자, 개발 전문가 페르소나, 게임 설계자 페르소나와 코드 및 데이터 근거로 의견을 교환했다. 이 역할은 제품 코드를 수정하지 않았다.

## 확인한 근거

- [공유 콘텐츠](../../shared/content.json): 마량은 노숙과 합쳐 제갈량, 정욱과 합쳐 사마의가 된다. 두 결과의 기본 공격 기여는 모두 초당 120이지만 제갈량은 촉, 사마의는 위 태그다. 현재 진영 강화와 어느 재료를 보존할지가 분기 판단에 영향을 준다.
- [서버 코어](../../server/core/index.ts): 조합은 정확한 소유 유닛 ID를 소비하고 새 ID의 결과를 재료 중 가장 낮은 배치칸에 생성한다. 파견 중인 유닛은 조합 재료로 사용할 수 없다. 자동 공격은 가장 오래 살아 있는 개인 적 하나를 대상으로 하며, 별도의 광역·둔화·탱킹 능력은 없다.
- [검토 시작 시 UI](../../playtest/app.js): `materials()`는 같은 종류 중 첫 유닛부터 재료로 고른다. 기존 선택 집합은 최대 두 기를 스토리에 파견하기 위한 것이다. 선택 유닛 진화를 추가할 때 그대로 재사용하면 선택한 개체 대신 다른 동일 유닛이 소비되거나, 진화 선택이 파견 선택과 섞일 수 있다.
- [게임 규칙](../GAME_DESIGN.md): 스토리는 45초 제한이며 실제 병력이 개인 방어에서 빠진다. 현재 행동 계약에는 수동 복귀가 없고 성공 또는 시간 종료에 복귀한다.

## 다른 역할에 대한 반론과 의견 수정

게임 설계자는 '결과 태그와 전후 공격 기여' 표시를 제안했다. 나는 공격 기여보다 **소비 개체와 다른 분기를 포기하는 비용**이 먼저라고 반박했다. 마량을 제갈량 재료로 쓰는 순간 사마의에 쓸 마량도 사라지기 때문이다. 설계자는 이 우선순위를 수용하면서 모든 사용처를 기본 카드에 펼치면 모바일이 혼잡해진다고 반론했다.

이 반론을 받아들여 최종 권고를 수정했다. 기본 카드에는 소비 병력·결과·적용 강화만 두고, 다른 분기는 '다른 진화 N개' 펼침이나 고정 목표와 충돌할 때의 한 줄 안내로 제한한다. 상세 조합표를 작은 선택 패널 안에 다시 만들지 않는다.

설계자는 내 '남는 방어병력 수' 제안만으로는 영웅 한 기의 손실을 설명하지 못한다고 지적했다. 이를 수용해 **장수 이름 → 개인 방어 이탈 → 수동 복귀 불가 → 남은 임무시간 이내 복귀**를 먼저 표시하고 인원 수는 보조 정보로 낮췄다. 실제 복귀 시점은 성공 여부와 남은 시간에 따라 달라진다.

개발 전문가는 기존 서버 조합을 재사용한 성장 카드, 초상화·전장의 공통 벡터 원본, 서버 공격 신호와 네 단계 적 보행을 제안했다. 나는 공격 자세·보행 디테일보다 **선택 표시, 아군/적 구분, 파견 표시, 소모 재료 인지**를 먼저 통과시켜야 한다고 반박했다. 보행 단계 자체를 반대하는 것이 아니라 작은 화면의 행동 판단을 가리거나 저사양 성능을 소모할 때 우선순위를 낮추자는 제안이다. 개발 전문가는 네 단계가 공통 SVG 다리 자세의 전환이라 추가 UI 공간을 차지하지 않는다고 설명하고, 진한색·밝은색 이중 선택링과 낮은 동작 설정에서의 고정을 제안했다. 이를 수용해 단계 수 축소 요구를 철회하고, 네 단계 보행을 유지하되 선택 표시를 우선하고 실제 성능은 별도 검사로 확인하는 것으로 추천을 수정했다. 이 문서는 개발 담당자의 실제 구현 완료나 소비자의 미술 선호를 주장하지 않는다.

## 최종 권고

1. 선택한 유닛의 관련 진화만 가까이 보여준다. 재료가 부족한 분기도 숨기지 않고 부족한 이름·수를 표시해 다음 소환의 목표를 만들되, 실행은 서버 검증으로 확정한다.
2. 실행 버튼 가까이에 정확한 소비 병력과 '2기 → 1기'를 표시한다. 같은 종류를 여러 기 보유해도 선택한 개체를 소비하며 파견 중 재료는 제외한다. 결과의 새 ID·배치 위치가 달라질 수 있으므로 완료 후 결과에 포커스를 옮긴다.
3. 공격 기여를 비교한다면 선택한 한 기만이 아니라 **소비 재료 전체의 합**과 결과를 비교한다. 강화가 없을 때 마량 35 + 정욱 35 → 사마의 120이므로 순증은 50이다. '마량 35 → 사마의 120'만 보여주면 다른 소비 재료를 빠뜨려 이득을 과장한다. 숫자는 평균 공격 기여이며 최적 선택 추천이나 실전 처치 속도 보장이 아니다.
4. 촉 강화 5단계라면 다른 강화가 없을 때 제갈량은 평균 180, 사마의는 120의 공격 기여를 갖는다. 이처럼 이미 구현된 태그 차이를 설명한다. 광역 딜러·탱커처럼 존재하지 않는 전투 역할을 새 그림이나 설명에 붙이지 않는다.
5. 파견 정보와 진화 정보의 버튼·선택 상태를 분리한다. 과밀이 임박했을 때도 확인 팝업을 반복하기보다 실제로 빠질 장수와 복귀 제약을 버튼 가까이 명료하게 둔다.
6. 캐주얼한 표현에서도 내가 선택한 병력, 조합으로 사라질 동료, 파견 병력, 적의 구분을 우선한다. 낮은 동작 설정에서도 동일한 행동 판단을 할 수 있어야 한다.

## 다음 검증 항목 — 아직 수행한 이용자 실험 아님

- 동일 종류 두 기 중 뒤쪽 개체를 선택해 진화했을 때 선택 개체가 재료에 포함되고 다른 개체가 남는지 확인한다.
- 조합 결과가 다른 배치칸에 나타나도 새 결과를 바로 찾을 수 있는지 확인한다.
- 마량을 선택한 사람이 제갈량/사마의 분기를 보고 어떤 재료와 강화가 결정에 영향을 주는지 설명할 수 있는지 관찰한다.
- 파견된 재료 때문에 진화가 잠긴 이유와 스토리 성공/종료 후 가능한 행동이 보이는지 확인한다.
- 모바일에서 선택 테두리·진화 버튼·파견 상태가 공격 효과와 겹쳐 읽기 어려워지지 않는지 확인한다.

이 문서는 코드 기반 내부 토론 결과다. 위 관찰 질문에 답한 실제 이용자 수, 이해율, 만족도는 아직 없다.
