# 이름·동일 재료 조립·초반 경제 검토 — 2026-09-26

대상: 콘텐츠 `0.11.0-reignition`. 사용자 피드백 중 이름과 조합 구조를 검토한 **논의안**이다. 콘텐츠·코어·훈련·아트는 수정하지 않았다. 실제 인간 플레이테스트 참가자는 0명이며 아래 수치는 코드 확인과 확률 계산이다. 적 압박·고철 수입 실측은 코어 담당의 별도 경제 검토와 합쳐 판단한다.

## 결론

**최종 권고는 동일 기본 3기→개조, 서로 다른 개조→특급 이상으로 이어지는 혼합 구조와 구역별 기본 풀 4→6→9종을 함께 설계하는 것이다.** 첫 구역 10칸에 9종을 그대로 넣는 안은 권하지 않는다. 1-1에서 명확한 네 역할로 시작하고 슬롯이 12/14칸으로 커질 때 가족을 늘리면 사용자 제안의 단순한 첫 조립을 살리면서 교착을 줄일 수 있다. 동일 2기→상위 혼합과 현재 혼합식은 비교 대안으로 남긴다. 아래의 이름도 최종 확정 목록이 아니라 역할·조립식·외형을 함께 정하기 위한 후보다.

3기 조립이 ‘돈이 남는다’를 자동으로 해결하지는 않는다. 조립 재료비는 늘지만 칸이 차서 원하는 재료를 못 뽑으면 돈을 쓸 곳이 없어지는 시점이 더 빨라질 수 있다. 조립 변경·수입 축소·적 강화는 한 번에 적용하지 않는다.

## 확률: 첫 조립의 간격은 얼마나 달라지는가

먼저 **매번 기본 등급이고, 기본 9종이 독립·균등하게 나온다고 가정**했다. 보유를 소모하지 않은 n번 뽑기의 다중집합에서 ‘아무 한 종이라도 3기 이상’ 또는 ‘하나라도 조립식 완성’이 존재하는 확률이다. 실제 판의 승률·첫 조립 시간·정확한 만칸 비율이 아니다. 조립·판매·해금·소환 쿨다운·전투 중 수입을 반영한 시뮬레이션과 구분한다.

9종을 10번 뽑으면 중복 2개는 반드시 생기지만 3개는 보장되지 않는다. 동일 3기 확률의 정확한 유리수는 7회 `1,426,329 / 4,782,969`, 10회 `2,370,248,001 / 3,486,784,401`이다. 따라서 10칸을 모두 기본으로 채워도 **32.02%에는 첫 3기 조립이 없다**. 또한 아무 가족이 아니라 **미리 정한 특정 한 가족** 3기를 10회 안에 얻을 확률은 9.06%다. 목표 장수/로봇의 보장은 별개의 문제다.

실제 기본 확률 93%를 반영하고 나머지 등급은 기본 중복에 기여하지 않되 칸은 차지하는 모형으로 계산하면, 기본 한 종 3기 완성은 7회 **24.72%**, 10회 **59.14%**다. 개조·특급 직접 소환은 이미 강한 로봇을 얻는 이득이 있으므로 이 값의 나머지를 ‘성장 실패율’이라고 부르면 안 된다.

### 재현 가능한 정확한 점유 DP

아직 3개가 없는 상태에서 한 개씩 있는 종류 수를 a, 두 개씩 있는 종류 수를 b로 둔다. 새 종류는 `(a+1,b)`에 `(9-a-b)`가지, 한 개 있던 종류는 `(a-1,b+1)`에 a가지로 간다. 두 개 있던 종류를 다시 뽑는 경로는 3개 완성이므로 제외한다. 생존 경로 수를 전체 `9^n`에서 빼면 완성 경로 수다. 아래는 난수를 사용하지 않는 BigInt 전수 상태 계산이다.

```js
function tripleFraction(n) {
  let states = new Map([['0,0', 1n]]);
  for (let draw = 0; draw < n; draw++) {
    const next = new Map();
    const add = (a, b, paths) => {
      const key = `${a},${b}`;
      next.set(key, (next.get(key) || 0n) + paths);
    };
    for (const [key, paths] of states) {
      const [a, b] = key.split(',').map(Number);
      if (9-a-b) add(a+1, b, paths * BigInt(9-a-b));
      if (a) add(a-1, b+1, paths * BigInt(a));
    }
    states = next;
  }
  const total = 9n ** BigInt(n);
  const notReady = [...states.values()].reduce((a, b) => a+b, 0n);
  return [total-notReady, total];
}
```

혼합식 비교는 기본 종류 보유 여부의 9비트 마스크 512개로 상태를 전개하고, 완성식이 생긴 경로를 제외하는 동일 방식으로 계산했다. 93% 모형은 `(a,b)`에서 상위 등급 7%의 제자리 전이와 기본 전이 93%를 사용했다. 표의 소수는 계산값을 반올림했다.

## 이름은 실제 역할·외형·가족을 함께 바꾼다

기본은 알아볼 수 있는 물건, 개조는 그 물건의 용도가 커진 기계, 특급 이상은 서로 다른 장치가 합쳐진 설비로 정한다. `봇`은 기본 가족에만 반복하고 상위에서 ‘대장/박사/마더’ 같은 추상 직함을 줄인다. 도감·전장·초상·조립식에서 같은 명칭을 사용한다. 저장된 진행과 연결된 내부 ID를 한꺼번에 개명할 필요는 없다.

## 3기안의 비용은 강화 수치만으로 보이지 않는다

무강화 볼트봇은 18/초, 현재 볼트가드는 61/초다. 같은 볼트봇 3기라면 재료 합 54→61로 **약 13% 증가**에 그친다. 세 자리에서 한 자리로 줄어 커버하는 길이와 동시 교전 지점은 감소하므로 실전에서는 약해질 수도 있다. 짧은 화염 사거리는 이 문제를 더 크게 만든다. 바람도 주 대상 0.8배와 추가 피해, 냉동은 적용 대상 수, 전격은 연쇄 발생을 함께 보아야 한다.

개조 공격력을 일괄 1.5배로 올리면 재료비 증가는 상쇄해도 직접 개조 6.8% 소환 가치·특급 재료 효율·보스 난도가 같이 바뀐다. 조립 전 재료 **전체**의 실전 기여와 결과를 비교해야 한다. 첫 단계만 3기로 바꾸고 상위식을 그대로 두면 바닥 재료 수는 특급 4→6, 전설 12→18, 궁극 36→54로 증가한다. 이는 재료 재사용 없는 조합나무·직접 상위 소환 없음 기준이며 실제 지출 확정액이 아니다.

| 1-3~1-5 | 14/16/20 | 위 6종+토치봇(shu_guard)+송풍봇(shu_rider)+냉풍봇(wu_rider), 총 9종 | 더 큰 보관 공간에서 상위 혼합과 가족 선택을 확장 |

풀은 계정이 성장했다고 1-1 재도전까지 9종으로 넓히지 않고 **구역별로 고정해 공개**한다. 구역 선택에 이번 원정의 뽑기 가족을 보여 준다. 숨은 확률 보정이나 실패 횟수에 따른 보정은 없다. 기본 93%/개조 6.8%/특급 0.2%의 등급 분포는 우선 유지하고, 기본과 직접 개조는 각각 해당 구역에 열린 가족 안에서 균등 추첨한다. 특급 직접 소환은 기존 희귀 대박으로 유지하는 방향이며, 조립 해금과 직접 획득 가능 여부를 혼동하지 않게 한다.

제안 풀의 수학적 효과는 다음과 같다. 같은 점유 DP에서 종류 수만 바꿨으며 나머지 가정은 앞 표와 동일하다.

| 조건 | 기본만 뽑았을 때 아무 가족 3기 | 기본 93%·상위 7%가 칸을 차지할 때 기본 3기 |
| --- | ---: | ---: |
| 3종 / 7회 | 100% | 92.77% |
| **4종 / 시작 7회** | **84.62%** | **74.62%** |
| 4종 / 9회 | 100% | 96.22% |
| **4종 / 첫 구역 만칸 10회** | **100%** | **99.01%** |
| 6종 / 둘째 구역 만칸 12회 | 99.66% | 97.16% |
| 9종 / 셋째 구역 만칸 14회 | 96.89% | 92.28% |

3종은 기본 7기부터 조립이 보장되고 네 역할 중 하나를 빼야 한다. 4종을 권하는 이유는 첫 조립을 충분히 자주 제공하면서 사거리·범위·감속·단일의 선택을 남기기 위해서다. 무료 유닛이나 추가 슬롯을 주지는 않지만 특정 가족의 집중도와 소환 가치는 바뀐다. 따라서 ‘공짜 전투력은 없으니 기존 밸런스도 그대로’라고 주장하지 않는다. 특히 가족별 개조 스탯·상위 혼합식·각 구역의 클리어 보상을 이 명단에 맞춰 검증해야 한다.

### 대안: 초반 재료 선택권 한 번

9종을 유지한 채 원하는 재료 1기를 무상 지급하면 당장 한 판의 성장 예산이 늘고, 이후 만칸에서의 9종 교착은 남는다. **이 방식은 추천하지 않는다.** 선택권을 비교하려면 새 무료 유닛보다 기존 일곱 번째 20고철 뽑기 한 번을 기본 종류 선택으로 바꾸는 방식이 낫다. 앞 여섯 기가 모두 9종 균등 기본인 조건에서 중복 쌍이 있을 확률은 88.62%이므로 선택한 일곱 번째로 그 가족 3기를 만들 수 있다. 나머지 경우에는 선택권 하나로 3기를 만들 수 없다.

이 대안도 선택 UI·한 번만 적용하는 규칙·목표 가족 운의 변화가 생기며 장기 슬롯 교착은 그대로다. 유료 선택권·실패 후 결제·추가 광고 보상으로 연결하지 않는다. 비교 순서는 **4→6→9 풀+동일3 권장안**, **9종 유지+동일2 대안**, **현 혼합식 대조군**이며, 선택권 방식은 첫 둘보다 우선하지 않는다.

## 막힘을 줄이되 공짜 전투력을 주지 않는 접근

1. **공개된 풀의 첫 가족은 모두 열어 둔다.** 모은 세 기가 레시피 잠금 때문에 막히지 않게 한다. 4→6→9 공급 확장과 이후 혼합에서 진행 목표를 만든다.
2. **소비 개체와 남는 자리는 유지한다.** 동일 재료라도 실제 ID 세 개와 기준 자리를 선택하게 하고 파견 중 개체는 제외한다. 기본 카드에는 `2/3` 같은 수량과 결과 역할, 상세에는 다른 상위 사용처를 둔다.
3. **판매는 손실이 있는 선택으로 남긴다.** 자동 판매·무상 재뽑기·완성 재료 지급·슬롯 초과 보관으로 숨겨서 해결하지 않는다. 7 환급과 다시 뽑을 때 13 순손실을 이해하게 하되, 설명을 추가했다고 교착이 해결됐다고 주장하지 않는다.
4. **막힘의 원인인 입문 풀을 먼저 좁힌다.** 권장안은 위의 4→6→9 공개 풀이다. 9종을 처음부터 모두 유지해야 한다면 동일 2기가 대안이다. 슬롯·수입·무료 재료를 동시에 늘려 증상을 덮지 않는다.

권장안의 가족 공급·첫 조립을 독립 실험하고, 여전히 만칸 판매 반복이 핵심 경험이면 추가 경제 조정 전에 원인을 검토한다. 가방·상점·천장 같은 새 시스템을 먼저 붙여 복잡성을 늘리는 순서는 권하지 않는다.

## 검증 순서와 팀 논의

먼저 같은 적·수입·슬롯·시드군에서 현재 혼합 / 9종 동일2+상위혼합 / 9종 동일3+상위혼합을 비교하고, 동일3의 풀만 4→6→9로 바꾼 권장안을 추가해 원인을 분리한다. 새 이름은 소비 규칙 이해에 도움이 되는지 별도로 본다. 첫 조립 tick의 중앙값·상위 분위, 처음 10칸 도달 시 조립 가능 여부, 만칸에서 머문 시간, 판매 재뽑기 횟수/순손실, 조립 전후 적 처리와 시설 피해, 전투 중 고철 잔액과 **쓸 수 있는데 안 쓰는 것/쓸 수 없는 것**을 나눠 기록한다. 첫 조립이 없는 판도 표본에서 제외하지 않는다.

현재 자동 정책은 만칸이면 최저 추정 기여 로봇을 반복 판매해 재뽑는 행동이 있다. 코어 담당의 지적을 수용해 ‘판매 없는 보유형’과 ‘복제 두 기를 보존하는 목표형’도 비교해야 한다. 봇이 돈을 소진했다는 이유로 사용자의 돈이 남는 경험을 반박하지 않는다. 조립 구조의 독립 비교가 끝난 뒤 적 압박·수입을 조정한다.

UX 담당은 “규칙이 단순하면 플레이도 쉬워진다”는 가정에 반박했다. 9종/10칸의 교착과 65% 판매 손실을 벌금처럼 만들 수 있다는 의견을 수용해, 단순 판매 안내를 해결책으로 제시하지 않고 3기안의 채택 조건에 실제 막힘 검증을 추가했다. 설계 측은 공급만 늘려도 만칸 교착이 풀리지 않고 슬롯만 늘리면 재료 보관을 강요할 수 있다고 반박했고, 두 담당 모두 세 축을 동시에 바꾸지 않는 데 동의했다.

훈련은 별도 설계가 필요하다. 예를 들어 동일3을 가르친다면 처음 싸우는 두 로봇을 같은 가족으로 바꾸고, 세 번째 불필요한 로봇을 판매한 뒤 같은 가족의 세 번째 재료로 조립하는 3칸 흐름을 검토할 수 있다. 이때 현재 냉동/레이저 조합의 전투와 같은 적을 보존하는 교육 효과, 개조 한 기의 720HP 보스 처치 시간을 다시 확인해야 한다. 이는 훈련 수정 제안이며 현재 동작을 바꾼 것이 아니다.

**정리하면 사용자 제안의 동일3→상위혼합을 채택할 설계 방향은 구체적이며, 이를 지탱하는 초반 구조는 4→6→9 가족 공급이다.** 먼저 이 조합 구조와 가족 명단을 확정하고 이름·스탯·훈련을 맞춘 뒤 돈과 적 압박을 조정한다. 이 문서는 논의안이며 아직 아무 콘텐츠도 변경하지 않았다.
