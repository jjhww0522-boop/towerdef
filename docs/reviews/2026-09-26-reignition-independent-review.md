# 재점화 업데이트 독립 검토 — 2026-09-26

범위: 작업 중인 `0.11.0-reignition` 코어·공개 상태·콘텐츠·자동 정책, 앱의 임무/공세/지원/결과 연결, 신규 그래픽·음향의 출처. 다른 담당자의 파일을 수정하지 않고 발견 사항을 전달했다. CSS는 검토 시점에 작업 중이어서 실제 DOM 겹침·모바일 가독성은 이 보고서의 통과 판정에 포함하지 않는다.

심각도는 P0 실행/저장 차단, P1 주요 플레이 판정 또는 흐름 오류, P2 제한된 상황의 표시·설명 불일치로 분류했다. **이번 코드 검토에서 P0/P1은 발견하지 않았다. 최초 P2 네 건과 후속 통신 시각 P2 한 건 모두 수정 확인을 마쳤다. 이 검토 범위의 미해결 발견 사항은 없다.** 실제 인간 플레이테스트 참가자는 **0명**이며 아래 자동 검사와 구분한다.

## 통신 시각 후속 검토 — 해결

최종 재검토: `operation-model.mjs:4`의 `milestoneTick`이 `ceil(totalWaves × threshold) × waveTicks`를 사용한다. 추가 회귀를 포함한 `node --test tests/operation-model.test.mjs` **5/5 통과**. 실제 코어의 `expeditionProgress`와 결합해 5구역 × 중간/경고 2종의 **10개 경계**를 직접 검사했다. 각 발신 직전 tick에는 해당 통신이 없고, 발신 tick에는 기록 시각과 실제 시각이 같았다. 최종 중간/경고 시각은 1번 90/165초, 2번 160/260초, 3번 220/360초, 4번 300/525초, 5번 450/775초다.

아래 표는 수정 전 발견 이력으로 보존한다.

요청받은 실제 통신 시각을 추가 확인해 다음 P2를 root에 전달했다. `expeditionProgress`의 진행률은 완료한 웨이브 수/전체 웨이브 수여서 계단식이다. `missionBeats`의 조건은 그 값을 사용하지만 기록 시각은 `floor(totalTicks × .5/.85)`로 계산해 실제 발신보다 빠르다. 현재 코어의 실제 `expeditionProgress`와 결합해 재현한 값은 아래와 같다.

| 구역 | 중간 통신 실제 / 기록 초 | 경고 실제 / 기록 초 |
| --- | --- | --- |
| 1 | 90 / 90 | 165 / 153 |
| 2 | 160 / 150 | 260 / 255 |
| 3 | 220 / 210 | 360 / 357 |
| 4 | 300 / 300 | 525 / 510 |
| 5 | 450 / 450 | 775 / 765 |

권고는 `ceil(totalWaves × threshold) × waveTicks`로 기록 시각을 실제 조건과 맞추는 것이다. 이 지적은 로그 시각 정확성에 한정된다. 2번 경고는 채굴 완료 준비이며 보스 예고를 하지 않고, 나머지 구역 대사도 실제 보스 공격을 꾸며내지 않는다.

## 최초 발견 이력 — 아래 네 건 모두 해결

### P2-01 · 개인 종료 후 관제 기록의 시각과 내용이 계속 진행한다

- 위치: `playtest/operation-model.mjs:5`, `:6`, `:7`, `:8`의 `missionBeats`.
- 원인: 전역 `state.expedition.miningProgress`로 중간/경고 기록을 생성하고 결과 시각을 현재 `state.tick`으로 기록한다. 개인 패배 때 저장한 `player.result.elapsedTicks`와 `miningProgress`를 사용하지 않는다.
- 재현: `player={status:'defeated',result:{elapsedTicks:100,miningProgress:.05}}`, `state={tick:1700,rules:{totalWaves:12,waveTicks:150},expedition:{miningProgress:.94,phase:'mining'}}`로 호출하면 `opening:0, midpoint:900, warning:1530, result:1700`이 나온다. 실제 개인 원정은 100틱에서 끝났는데 이후 두 통신이 추가되고 패배 시간이 1700틱으로 변한다.
- 영향: 협동에서 먼저 패배한 뒤 동료를 관전하거나 재접속하면 개인 작전 기록을 믿기 어렵다.
- 권고: 종료된 플레이어의 기록은 결과 스냅샷의 시간/진행률로 고정한다. 전역 관제 기록을 의도한다면 개인 원정 결과와 명시적으로 구분해야 한다. root에 재현과 함께 전달했다.

### P2-02 · 재접속한 패배자의 도달 웨이브가 동료의 현재 웨이브로 바뀐다

- 위치: `playtest/app.js:652`, `showResult`의 `[state.wave, '도달 웨이브']`.
- 원인: 나머지 통계는 `player.result.battleStats`를 우선하지만 웨이브는 전역 현재값이다. 코어는 `server/core/index.ts:183`에 이미 개인 결과의 `wave`를 저장한다.
- 재현: 4인 방에서 3웨이브에 개인 패배 후 접속을 끊고, 동료가 8웨이브까지 진행한 뒤 다시 접속해 결과 창을 연다. 저장된 `player.result.wave=3`과 화면의 `state.wave=8`이 다르다. 이 흐름은 코드 경로 검토이며 실제 브라우저 재접속 재현은 후속 항목이다.
- 권고: `player.result?.wave ?? state.wave`를 표시하고 결과 스냅샷이 다른 전역 필드에 덮이지 않는지 검사한다. root에 전달했다.

### P2-03 · 보스의 공식 역할명과 전장 이름이 다르다

- 위치: `shared/content.json:8`의 보스 설명과 `server/core/index.ts:111`의 예고는 ‘거대 회수기’, `playtest/battlefield.js:787` 부근의 `enemy` 표시와 `playtest/app.js:615` 부근 훈련 대사는 ‘폭주 압축기’다. 줄 번호는 연출 담당의 동시 수정에 따라 이동할 수 있다.
- 재현: 일반 보스 예고/적 안내를 연 다음 보스의 Canvas 이름을 비교한다. 훈련 보스에도 코어가 `archetype:'boss'`를 부여하므로 `archetype` 존재 여부만으로 일반전투와 훈련을 구분할 수 없다.
- 권고: 일반/훈련을 포함해 이름을 하나로 맞추거나 명시적 훈련 상태로 구별한다. 연출 담당에게 전달했고, 단순 legacy 분기로는 훈련을 보존할 수 없다는 점도 후속 전달했다.

### P2-04 · 피해 통계의 범위를 짧게 명시해야 한다

- 위치: `playtest/app.js:652`의 ‘실제 피해’; `server/core/index.ts:486`과 스토리 공격 분기.
- 사실: 통계는 초과 피해를 제외한 본진 적 대상 실제 피해만 누적하며 공동 스토리 피해는 제외한다. 이 계산은 실행 계획의 계약과 일치한다.
- 재현: 협동 스토리에 강한 로봇을 파견해 공격한 뒤 결과를 보면 파견 피해가 수치에 포함되지 않는다. ‘실제 피해’만으로는 총 기여라고 오해하기 쉽다.
- 권고: ‘본진 피해’로 표시하거나 스토리 제외 설명을 붙인다. 잘못된 전투 계산으로 분류하지 않는다. root에 전달했다.

## 통과한 판정·계약

- `tests/tactics-encounters.test.mjs`, `operation-model.test.mjs`, `tutorial.test.mjs`, `attack-signals.test.mjs`를 실행해 **32/32 통과**했다. 기존 빌드의 콘텐츠가 `0.11.0-reignition`임도 확인했다. 전체 회귀·브라우저 결과를 대신하지 않는다.
- 공세는 웨이브별 상대시간으로 생성하며 `floor((waveTicks-1)/interval) × batchSize`의 예고 수가 실제 생성 수와 일치한다. 일반 구간 전환 직후 생성하지 않고 interval 후 첫 생성이라는 의미도 일치한다. 타입/경로 생성은 소환·배치 난수를 소비하지 않는다.
- 다섯 구역의 마지막 웨이브를 직접 조회했다. 2번 채굴장은 `next:null`이고 다른 네 구역은 실제 보스 시작 tick과 1기 예고를 반환한다. 2번은 채굴 종료이며 보스 제한을 요구하지 않는다.
- 훈련은 공세 예고가 null이고 전술 요청도 거부한다. 고정 소환·3적 전투·읽기 단계 정지·720HP 보스와 무보상 완료 테스트가 유지된다.
- 전술은 공통 400틱/40초. 과부하 60틱 동안 본진 피해 1.5배이며 파견 피해에는 적용하지 않는다. EMP는 사용 당시 적의 이동과 공성을 30틱, 보스는 10틱 정지한다. 이후 생성 적에는 적용하지 않는다. 앱 도움말과 판정이 일치한다.
- 전술 실패·재전송·다른 내용의 같은 seq·쿨다운 경계·구역 격리 테스트가 통과한다. 자동 정책도 서버 행동을 사용하고 무입력에 전술을 몰래 실행하지 않는다.
- 본진 피해는 남은 HP로 제한되어 과잉 피해가 통계에 들어가지 않는다. 개인 결과의 전투 통계는 중첩된 지원 횟수까지 복사한다. 후속 변경으로 이미 확정한 결과를 덮지 않는다.
- 신종 중장 공성봇은 고체력·저속·시설 피해 2배이며 속성 저항이 없다. 데이터 설명과 일치한다. 단일 화력/범위/냉동 조언은 일반 권고이며 승률·안전 판정으로 표현하지 않는다.
- 현재 콘텐츠의 3~5번 보스 체력은 25,500/59,500/114,750으로 이전 값의 85%다. 임무 대사는 체력을 하드코딩하지 않고 7/10/15분의 기존 준비시간을 유지한다.

## 자동 실험 해석의 한계

`compareCombatPolicies`는 5개 구역의 동일 시드군에 무입력·소환·조합·강화·파견과 지원 정책을 비교한다. 실제 이용자 승률이 아니며 ‘지원 없이 클리어 가능’은 지원이 누구에게나 선택 사항이라는 증명과 다르다. 코어의 지원 무사용 클리어 테스트는 초반 특정 시드 사례를 확인한다. 후반 정책별 결과는 구현 담당의 전체 실험 기록을 함께 읽어야 한다.

이후 [코어 담당의 900회 비교 기록](../playtests/2026-09-26-combat-balance.md)을 읽었다. 지원 없는 20시드 단독 파견 전략의 구역별 클리어는 20/20/14/15/13, 상시 과부하는 20/20/15/15/13이다. 이 표본에서 지원 필수화 징후는 보이지 않는다. 2번은 소환만으로 20/20 성공하며, 후반 숙련 정책의 남은 패배는 보스 시간 초과다. 따라서 적 역할·EMP가 모든 전략에 의미 있는 판단을 만든다고까지 결론 낼 수는 없다. 이 900회를 독립 검토자가 다시 실행한 것은 아니며 읽은 실행 보고서와 위 32개 직접 실행을 구분한다.

적 이동 속도·뭉침이 바뀌면 소환/처치 시점과 이후 난수 소비 순서도 달라질 수 있으므로 같은 시드의 결과 차이를 특정 버튼 하나의 독립 인과 효과로 보고하지 않는다.

## 출처 추적 검토

`casual-art.js`의 신규 적은 직접 작성한 SVG 도형이고 `combat-audio.js`는 오실레이터·필터·결정적 노이즈 생성 코드다. 이번 diff에서 외부 이미지/음원 로딩을 새로 추가한 경로는 확인되지 않았다. 제작 담당에게 외부 입력 여부를 확인했고, [참고 대장](../reference/2026-09-26-reference-ledger.md)에 실제 파일·방식·날짜를 추가했다. 기존 `assets/manifest.json`의 전체 권리 상태를 재검증했다는 뜻은 아니다.

독자 대사 모듈은 실제 구역 목표와 일치한다. 2번은 보스가 없고, 자원 운반이나 시설 수리 같은 추가 조작을 요구하지 않는다. 공식 6작품의 관찰은 참고 원칙으로 기록되어 있으며 특정 외형·대사·수치·UI 복제 허락으로 표현하지 않았다.

## 아직 하지 않은 검증

작업 중인 CSS의 실제 화면, 모든 신규 팝업의 포커스 순환·키보드 동작, 긴 5번 구역의 실제 휴대폰 성능/음향, 사람이 공세를 이해하는지는 이 검토에서 확인하지 않았다. 후속 브라우저 캡처와 사용자 관찰이 필요하며 이 문서는 출시 인증이 아니다.
