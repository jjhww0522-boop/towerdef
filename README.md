# Towerdef — 폐품로봇 원정대 (가제)

아이폰을 우선 지원하는 **4인 협동** 모바일 랜덤 디펜스 게임을 개발하는 저장소입니다.
자원이 고갈된 지구를 위해 행성으로 원정을 떠나, 자원을 채굴하고 폐품 로봇으로 습격을 막은 뒤 탈출하는 스테이지 게임을 목표로 합니다. 각자의 방어 구역과 별도의 공동 목표인 **스토리**를 둡니다.
고철로 **로봇 뽑기**를 하고, 정해진 조합식으로 더 강한 로봇을 **조립**합니다. 목표 로봇을 못 만들면 다른 조합으로 전환할 수 있으며, 첫 스테이지는 배우며 클리어할 만하게, 이후는 실패 위험을 크게 높이는 방향입니다. 친근한 폐품 로봇과 거칠고 묵직한 우주 생존 분위기를 함께 살립니다.

**현재는 브라우저에서 플레이할 수 있는 개발용 버전입니다.** 로봇 29종·조합식 20개, 첫 행성의 스테이지 5곳과 최대 4인 로컬 협동을 제공합니다. 첫 스테이지는 적 과밀 관리와 보스 처치, 후속 스테이지는 채굴기·엔진 보호와 보스 처치가 목표입니다. 시작 조합식 5개에서 스테이지 클리어로 11개를 자동 해금하고, 나머지 4개는 연구 크레딧으로 선택 해금합니다. 기록은 로컬 서버 파일에 저장합니다.

> 회사에서 이어갈 때는 [최신 인계 및 페르소나 토의](docs/LATEST_HANDOFF.md)를 먼저 읽으세요.

`0.10.0-growing-expedition`은 **홈 → 행성 선택 → 전투**로 화면을 분리합니다. 연구소는 홈에서 필요할 때 엽니다. 전투의 분리된 하단 띠를 없애고 로봇 뽑기는 전장 오른쪽 아래, 로봇·조립·강화는 왼쪽 아래에 배치했습니다. 로봇 설명과 관리 창을 열어도 전장 크기는 바뀌지 않으며 상자는 화면 높이 30% 이내입니다. 시설 방어에서는 적이 도착 지점에 멈춰 계속 공격하며, 시설 체력이 0이 되면 해당 플레이어가 패배합니다. 냉동은 이동 속도만 늦춥니다. 시설 체력·피해량은 시험값이며, 실제 기기·사람의 장시간 플레이 검증과 Unity 화면 이식은 아직 필요합니다. 엔진은 최대 5개이며 일반·배속 연습의 새 원정당 1개 사용, 서버 시계로 30분마다 1개 회복합니다. 충전 창과 서버 구매 검증 연결점은 있지만 실제 스토어 결제는 연결 전이며 비활성입니다. [엔진/결제 연결 상태](docs/ENGINE_BILLING.md), [챕터 1 구현·검증](docs/plans/2026-09-23-engine-chapter-one-design.md)을 참고하세요. 엔진과 다섯 맵 브라우저 검사는 빌드 후 `npm run test:chapter`로 실행합니다.

`0.6.0-position-combat`에서는 빈칸에 무작위로 로봇을 뽑고, **선택한 재료 로봇의 자리에서 조립**합니다. 화염의 근거리 고화력, 바람의 범위 공격, 냉동의 감속, 레이저의 장거리 단일 공격과 기존 연쇄 전격을 시험할 수 있습니다. 로봇을 선택하면 사거리가 표시되고 설명 상자는 선택한 로봇의 반대쪽에 뜹니다. 화면을 회전해도 전투 위치와 사거리 판정은 동일합니다. 기존 29종 이름·조합식에 시험용 속성을 배정한 상태이며, 생활용품 로봇의 최종 목록·아트와 별도 장기 협동 모드는 기획 단계입니다.

배경은 먼 행성과 별빛이 보이는 야외 채굴지이며 행성마다 크레이터·푸른 사구·보랏빛 광맥으로 구분합니다. 웨이브·과밀 경보와 보스 체력을 전장에서 확인하며, 효과음과 움직임 줄이기는 설정에서 바꿀 수 있습니다. 유닛 선택창의 **판매**에서 회수할 고철을 확인한 뒤 로봇을 판매할 수 있습니다.

챕터 1은 순환·세로·가로·양쪽 진입·십자 진입으로 나뉩니다. 열린 길의 적은 시설 앞에 멈춰 공격하며, 배치 칸은 길 양옆의 받침대로 표시합니다. 화염 빨강/주황, 냉동 파랑, 바람 민트, 레이저 보라, 전격 노랑으로 본체·무기·효과 색을 통일했습니다. [경로·색상 구현과 검증](docs/plans/2026-09-23-diverse-routes-element-colors.md)을 참고하세요.

챕터 1은 배치 한도가 **10/12/14/16/20기**, 방어 시간이 **3/5/7/10/15분**으로 늘어납니다. 2번은 5분 채굴 완료 시 종료하고, 나머지는 방어 뒤 보스를 제한시간 안에 처치합니다. 로봇 뽑기는 성공한 뽑기부터 **0.7초** 기다리며 첫 뽑기는 즉시 가능합니다. 홈의 **기동 훈련**은 엔진 없이 3칸에서 뽑기·판매·선택한 자리 조립·보스전을 연습하고 완료 기록만 남깁니다. [성장형 원정·튜토리얼 규칙과 검증](docs/plans/2026-09-23-growing-expedition-tutorial.md)을 참고하세요.

## 바로 실행하기

Node 22 이상에서:

```powershell
npm ci
npm test
npm run dev
```

브라우저에서 `http://127.0.0.1:7351`을 열고 홈의 **스테이지 선택 → 출발 · 엔진 1**을 누릅니다. 기본 1배속 원정은 성과를 저장하고, 3·6배속 연습은 연구 크레딧·행성 해금·전적을 지급하지 않습니다. 홈 또는 스테이지 목록의 **함께하기**에서 같은 방 코드로 서로 다른 브라우저 프로필의 최대 네 접속을 연결할 수 있습니다. 로컬 전용 서버이므로 외부 기기 접속은 제공하지 않습니다. Unity 경로는 [클라이언트 안내](docs/CLIENT_SETUP.md)를 따릅니다.

원정 기록은 `.towerdef-data/profiles.json`, 기록에 접근하는 인증 정보는 브라우저에 저장합니다. 서버 재시작 후 기록은 유지되지만 진행 중이던 방은 복구되지 않습니다. 이 데이터와 인증 정보는 Git에 포함되지 않으며 집과 회사 사이의 계정 동기화는 아직 제공하지 않습니다.

현재 구현과 검증 결과는 [최신 인계](docs/LATEST_HANDOFF.md), 이번 범위는 [행성 원정 구현 계획](docs/plans/2026-09-21-expedition-progression.md)에 정리했습니다. [이전 화면 품질 기록](docs/VISUAL_QUALITY.md)과 [반복 개발 결과](docs/ITERATION_RESULTS.md)는 당시 구현의 이력입니다.

Windows PowerShell에서 `npm` 스크립트 실행이 차단되면 같은 명령을 `npm.cmd ci`, `npm.cmd test`, `npm.cmd run dev`로 실행합니다. 모바일 레이아웃 자동 검사는 서버와 검증용 브라우저를 준비한 뒤 `npm run test:mobile`로 실행합니다.

원정·연구 통합 검사는 `npm run test:expedition`입니다. 빌드 후 격리된 테스트 서버와 임시 저장소를 직접 실행하며 `CHROME_PATH`로 Chromium 실행 파일을 지정할 수 있습니다. 종결 테스트는 제어된 서버 전투 상태를 사용하며 30분 실제 사람 플레이를 대신하지 않습니다.

전투 연출 검사는 `npm run test:combat`입니다. 실제 서버 공격·조립·웨이브·보스와 브라우저 효과음/무음 경로를 확인하고 `artifacts/`에 화면과 보고서를 남깁니다. `COMBAT_VIDEO=1`로 실행하면 영상도 기록합니다. 데스크톱의 자동 브라우저 프레임 관찰은 아이폰 성능 검증이 아닙니다.

위치·사거리 통합 검사는 빌드 후 `npm run test:position`입니다. 자체 테스트 서버에서 세로·가로·데스크톱의 조립 위치 보존, 사거리 표시, 감속 상태와 회전을 검사합니다. 브라우저 검사에는 설치한 Chromium 계열 브라우저 경로를 `CHROME_PATH`로 지정할 수 있습니다.

모바일 화면 흐름과 시설 방어 검사는 빌드 후 `npm run test:flow`입니다. 격리된 서버에서 홈·연구소·행성 선택·전투·재접속·귀환과 시설 피격/파괴를 확인합니다. 후속 행성 검사는 해금과 적 배치를 통제한 서버 상태를 사용합니다. 설계와 구현 범위는 [모바일 게임 흐름](docs/plans/2026-09-22-mobile-game-flow-design.md)에 기록합니다.

- [개발 환경·프로토콜·검증 범위](docs/DEVELOPMENT.md)
- [이번 구현 계획](docs/IMPLEMENTATION_PLAN.md)
- [애니메이션 제작·에셋 출처](docs/ART_PIPELINE.md)

Unity 없이 서버 빌드와 자동 테스트는 실행할 수 있습니다.

## 집에서 이어가기

처음 내려받는 경우:

```powershell
git clone https://github.com/jjhww0522-boop/towerdef.git
cd towerdef
git status
```

이미 복제한 경우, 먼저 로컬 변경을 확인하고 `main`을 업데이트합니다.

```powershell
git status
git switch main
git pull --ff-only origin main
```

로컬 수정 때문에 전환이나 갱신이 실패하면 그 수정을 보존한 뒤 충돌을 해결합니다.
강제 초기화로 덮어쓰지 않습니다.

새로운 개발 세션에는 다음과 같이 요청하면 됩니다.

> AGENTS.md, docs/GAME_DESIGN.md, docs/LATEST_HANDOFF.md를 읽고 현재 상태를 확인해줘.
> 합의한 게임 방향을 유지하면서 제작팀의 기본안을 바탕으로 자율적으로 개발을 이어가줘.
> 아직 확인되지 않은 환경·계정 정보는 추측하지 말고, 독립적으로 가능한 작업부터 진행해줘.

## 방향

- 개인 방어는 각자가 책임집니다. 동료가 내 라인의 적을 직접 제거하는 기능은 넣지 않습니다.
- 첫 완성본은 4인을 목표로 합니다. 8인과 그 이상은 사용자가 원하는 확장 방향이며, 부하·화면·매칭·협동 테스트 후 지원 범위를 정합니다.
- 협력은 조난 신호 구조·중앙 전력 복구·탈출 항로 확보의 스토리 파견과 공동 보상에 집중합니다.
- 기본 전력은 로봇 뽑기와 확정 조립으로 만들며, 강한 로봇이 드물게 바로 나오는 대박도 둡니다.
- 리사이클·오비탈·스파크 계열, 보행·포탑·궤도 형태, 동력·연산·제어 특성에 강화 투자합니다.
- 목표 로봇을 완성하지 못하면 패배할 수 있습니다. 클리어를 보장하지 않습니다.
- 우주 고물 정거장의 로봇·조합·전장·그림을 독자적으로 제작합니다. 삼국지 기획과 이전 아트는 이력이며 현재 콘셉트가 아닙니다.

가제와 구체적인 콘텐츠는 출시 명칭이나 권리 검토가 완료된 결과물이 아닙니다.
시장 성공, 실기기 성능, 재미 검증 역시 아직 확인되지 않았습니다.

무료 기동 훈련은 홈에서 시작합니다. 튜토리얼의 터치·판매·조립·보스 전체 흐름은 `npm run test:tutorial`로 확인합니다(Chrome 실행 경로는 다른 브라우저 검사와 같이 `CHROME_PATH` 사용).
